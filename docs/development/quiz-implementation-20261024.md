## 候選資料與 API

`supabase/quiz.sql` 建立私有 `quiz_banks`、`quiz_versions`、`quiz_sessions`、`quiz_attempts`、`quiz_answers`。一般角色沒有直接資料表或內部 helper 的存取權。`quiz_action` 由 `auth.uid()` 與既有 `is_teacher()` 決定權限，忽略使用者傳入的 user_id。

教師操作：`list/get/save/publish/versions/sessions/open/monitor/close`。學生後端操作：`join/resume/submit`。教師只存取自己題庫／場次；學生須在場次班級的正式名冊中，教師不能代交。

文件 schema 1：`title`、`catalog`、`blocks[]`。區塊含穩定 `id`、`material` 與 `questions[]`；題目含穩定 `id`、`type(single/short)`、`prompt`、`options`、`answer`、`explanation`。內容格式為 `{text,media:[{kind:image/audio,url,alt}]}`，公式以 `$…$` 或 `$$…$$` 撰寫。選項使用穩定 ID，顯示標號不參與判分。題組不會拆散，內部題序固定。

草稿修改用 expected_revision 樂觀鎖；相同內容重試不增加 revision。固定版本由 bank_id＋revision 唯一決定，相同操作重試回傳同一版本。場次引用固定版本，不讀目前草稿；學生首次加入時把題序與選項序持久保存，重整不重新亂排。

學生回應只由白名單產生，未揭答時不提供 `answer`、`explanation`、`correct`。`immediate` 的單題送出後回傳解析；多子題區塊等本人完成整組。`complete` 等本人完成整份，不等其他學生。送答採 request_id 與 attempt_id＋question_id 防重，原始簡答保留。題序及揭答檢查都在後端交易中執行。結束場次後拒絕新答案，但原請求冪等重試及本人接回仍可讀。

## 明示暫定值與限制

- 選擇題初版為單選；簡答僅去頭尾空白後，逐一精確比較教師列出的可接受答案。未做語意 AI 評分、多選或教師覆核介面。
- 初版逐題依既定順序送答，一題只有一份答案；不先定義跳題、回改、重答或計時制度。
- 題組尚未完成時暫不回傳純正誤；這是保守後端行為，不是宣稱使用者已核准產品規格。
- 題組位置暫固定，只在單題區塊原位置間亂序；選項可獨立亂序。這保留整組位置待決空間。
- 名額暫上限 29 位學生＋1 位開場教師。SQL 層已測超額拒絕；不是雲端容量或媒體承載證明。
- 2026-10-24續作已補媒體位元組保存：固定版本走 Edge 候選函式，保存 SHA-256 私有物件，草稿保留來源網址；未揭答解析媒體另驗權。詳細候選設定與限制見 `supabase/functions/quiz-media/README.md`。舊本機版本不改寫。
- 媒體由 HTTPS 允許清單下載保存，沒有檔案選擇上傳、轉碼或跨瀏覽器聲音格式完整驗證。短效網址60秒，過期有重新載入入口；已發網址不會隨登出即刻撤銷。
- 教師／學生正式登入 adapter 已共用目前 SDK session，正式入口以合成 SDK 及本機 Auth／Storage 通過瀏覽器整合；migration、桶與函式均未套用或部署，真實 OAuth、正式名冊與 RLS 環境仍未驗收。

## 已核准並實作的學生介面契約（2026-10-24）

現行 dev-sop／new-page-checklist 規定可作答課程測驗使用 `quiz-module`＋`student_progress`；現行 quiz-module 需在前端提供答案評分。本案要求場次固定版本、後端判分與未揭答不送答案。只增加 save callback 無法化解這個衝突。

使用者已明確回覆「同意，依此接續學生介面（建議）」：`initQuizModule` 增加明確 opt-in 的 server 模式，透過 `quiz_action` 取得安全題目、送答與接回；既有週頁維持原模式。新場次正式紀錄以 `quiz_attempts/quiz_answers` 為準，教師從測驗監看查看，暫不映射 `student_progress` 或努力樹。

`shared/quiz-server.mjs` 為新模式共用控制器，`quiz-student.mjs` 是入口與 auth adapter。它不接收題目正解參數、不執行前端評分。正式模式沿用同學期 navbar 與 `initNavbarAuth()`；本機模式明示合成身分，不能冒充正式登入。未登入不渲染題目，換人立即清除畫面，舊請求結果以 generation 避免寫回新身分。

`admin-quiz.html` 的固定版本有「用此版本開場」，可分別設定揭答、題序與選項亂序，列出加入連結與場次。監看只顯示名冊姓名／班級座號及已答題數，不含排名或努力分數；點「開始監看」後每 8 秒更新，可暫停，切換監看或身分會停止舊迴圈。

學生入口為 `/grade6/115-1/quiz.html?session=<場次 UUID>`。本機另加 `local=1&student=1`，合成編號 1～31 只由本機測試伺服器識別；正式 RPC 不接受此合成身分標頭。加入連結只定位場次，不能取代登入與名冊驗證。

學生依序送答，成功後自行按下一題，可回看已保存題目。網路失敗保留原始答案及 request_id，暫停修改該次答案以避免不確定狀態下重交；可重試相同請求或更新保存狀態。若送達後回應遺失，重整會從後端找出下一未作答題。未送出的文字不做本機持久化，重新整理可能遺失；正式已保存作答不受影響。

課堂即時開關模組仍維持原規則；此監看迴圈是新場次教師頁的獨立生命週期，不修改既有 auth 的 focus/refocus 或週頁輪詢行為。後端仍是候選 SQL，未套用正式資料庫。
