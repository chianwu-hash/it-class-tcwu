# 共同營地：語音訊息與畫圖評估（尚未實作）

使用者在答題介面收尾時提出：三年級打字慢，請教與回覆能否用語音或畫圖。結論：兩者皆可，應作為和文字平等的表達方式；不強制補打文字，也不增加主答題畫面的負擔。

## 建議操作

營地請教／回覆輸入區保留「打字、說一段、畫給夥伴看」。預設簡短輸入，不同表達方式按需展開；同一則可有一段語音＋一張畫圖，文字可略過。仍綁定題目／請教串，不另開無關的大聊天室。

- 語音：點「開始錄音」→顯示錄音中與秒數→點停止→試聽／重錄／送出。建議首版上限 30 秒，可調整；採點一下開始／停止，滑鼠與觸控都方便。收件人點播放，不自動播放。拒絕麥克風權限時保留文字／畫圖選擇。關閉、離房與登出立即停止音軌。
- 畫圖：沿用現有手寫板的筆畫、復原與清除，提供空白紙，後續可加「在這題圖上圈一圈」。預覽後送出，在訊息中呈現縮圖，點開放大。保留題號與原題關聯；不必重畫題目。
- 通知延用目前規則：相關請教／回覆顯示提示，聊天只 badge。未播放音訊不能因捲到底就冒稱「已聽完」；首版未讀只是「已查看訊息」，不要顯示對方已聽懂或已聽完。
- 學習紀錄可留下「用語音說明卡住的地方」「用圖提示夥伴」等努力片段，不依音檔長度／張數排行、不額外計葉花。原達標、訂正與回顧政策不變。

## 現有程式可以沿用多少

| 項目 | 現況 | 新增工作 |
|---|---|---|
| 畫圖操作 | `quiz-past-manual.js` 已有 SVG 筆畫、復原、清除與正規化座標 | 抽離純畫圖元件，移除作答確認／判分文案，保留原考古介面；新增訊息草稿／送出與回放 |
| 音訊播放 | 題庫已有授權音訊讀取、原生播放器 | 可沿用播放體驗；需新增錄音、格式偵測、試聽、停止音軌與上傳 |
| 訊息資料 | notes 僅有文字；ask/reply/chat 要求 1～600 字 | 加媒體附件契約，允許「有附件但無文字」；不能只是放一顆錄音按鈕 |
| 多人同步 | 現有 notes + 房間 revision／快照 | 同步小型附件 ID／型別／時間／尺寸，不在每次快照推送音檔 base64 或完整大圖 |
| 權限 | 題目媒體服務僅處理已授權題庫媒體 | 另建小隊訊息媒體授權；不能把上傳音檔當題庫媒體繞過檢查 |

## 實作邊界與驗收

語音使用瀏覽器 `getUserMedia` + `MediaRecorder`，需要 HTTPS／localhost 與麥克風允許；錄音格式須依 `isTypeSupported()` 偵測並驗證目標裝置能互播，不固定假定 WebM。首版不做即時通話、不依賴 AI 轉文字。30 秒、24～48 kbps 若能被裝置採用，編碼本體約 90～180 KB（另有封裝開銷）；此為估算，不是實測或成本保證。

音檔採私有 Storage，附件登記 room/user、型別、實際位元組與長度；後端驗證成員與可用格式／大小，快照只回必要 metadata，點播放才取媒體。限制 MIME 與大小可用 bucket 規則配合後端內容驗證。沿用 requestId，先上傳暫存再原子連結訊息，失敗重送不重複發布；處理失敗未連結檔案的清理。畫圖存限定格式的筆畫資料，嚴格限制點數／大小，不接受任意 SVG/HTML。

語音原始 Blob 不能直接塞入目前 JSON 草稿或 localStorage。未送錄音關閉營地先保留當頁記憶體；若要求「儲存退出」後仍接續，需登入授權的暫存附件與過期清理，不能宣稱沿用文字 save_draft 就完成。學期內保留與紀錄冊音檔的保存期限需在實作前定案。

建議先以隔離合成小隊原型同時驗證「語音請教→畫圖回覆→回題目再試」，再接資料庫。必測麥克風拒絕／沒裝置／錄音中離房、三種常用裝置互播、失敗重送、未授權存取、兩機接收、畫圖草稿與網路慢時的提示。教室多人同時說話、耳機可用性與手機鍵盤遮擋須實機確認。

參考官方技術文件：[getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[MediaRecorder 格式偵測](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)、[Supabase 私有 Storage](https://supabase.com/docs/guides/storage/buckets/fundamentals)、[上傳大小限制](https://supabase.com/docs/guides/storage/uploads/file-limits)。
