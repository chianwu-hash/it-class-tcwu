# 三年級成績計算規則

> 定案日期：2026-05-23
>
> 適用範圍：三年級資訊課網站中，已寫入 `student_progress` 的資訊素養答題與中英打闖關紀錄。

---

## 成績項目

三年級系統成績分成兩項獨立成績：

1. 資訊素養答題成績
2. 中英打闖關成績

兩項成績先分開計算，不在本規則中合併成單一總分。若日後需要期末總成績，再另訂兩項權重。

這兩項成績的學習進度可以整合顯示在「努力樹」頁面中，但努力樹不應顯示正式成績或百分比分數。較妥當的呈現方式是進度條、累積完成狀態、葉子 / 花朵獎勵與鼓勵文字，例如「資訊素養任務完成 4 / 7」、「中英打闖關累積 38 / 108 點」。努力樹頁面只讀取並呈現進度，不另行寫入或修改成績資料；正式成績仍依 `student_progress` 與成績設定檔在結算時另外計算。

本站的後台成績功能只需要動態更新與匯出，不需要把結算成績寫入資料庫。正式成績計算與登錄會在校務系統進行；本網站只提供依學習紀錄推算出的參考數據與匯出檔。

---

## 共用資料來源

成績只使用 `student_progress` 中的資料，不使用 `localStorage` 或畫面顯示狀態推算。

主要欄位：

- `user_id`
- `week_code`
- `activity_key`
- `current_level`
- `completed`
- `score`
- `updated_at`

活動清單與每個打字活動的總關數，應使用一份明確設定作為 source of truth。現階段可參考 `shared/reward-tree-config.js` 的 `REWARD_TREE_ACTIVITIES`，但正式成績功能實作時可以抽成更通用的成績設定檔。

目前所有正式資訊素養測驗與中英打闖關活動皆納入成績計算。若日後有測試活動、補充練習、臨時活動或其他不納入成績的活動，需由老師明確指定後再從成績設定檔排除。

## 一、資訊素養答題成績

### 納入活動

納入 `type = "quiz"` 的資訊素養測驗活動。

目前已知活動包含：

- 第 6 週：`safety_quiz_1`
- 第 7 週：`privacy_quiz_1`
- 第 11 週：`etiquette_quiz_1`
- 第 12 週：`media_literacy_quiz_1`
- 第 13 週：`internet_addiction_quiz_1`
- 第 14 週：`phishing_safety_quiz_1`
- 第 15 週：`screen_time_quiz_1`
- 第 16 週：`copyright_cc_quiz_1`

正式結算時，以成績設定檔中列入的 quiz 活動為準。

目前上述正式 quiz 活動全部納入。

### 單次測驗分數

單次測驗使用 `student_progress.score` 作為答對題數。

```text
單次測驗得分率 = score / 該測驗總題數
```

目前三年級資訊素養測驗多為 5 題，但實作時不可硬寫固定 5 題，應由活動設定或題目資料取得總題數。

### 總成績

```text
資訊素養答題成績 = 所有納入測驗的答對題數總和 / 所有納入測驗的題數總和 * 100
```

### 未完成測驗

結算日前：

- 可顯示「未完成」
- 即時預覽可選擇只計算已完成項目，但必須清楚標示不是正式結算分數

結算日後：

- 納入但未完成的測驗以 0 題答對計算
- 該測驗題數仍計入分母

## 二、中英打闖關成績

### 納入活動

納入 `type = "typing"` 的中英打闖關活動。

目前已知活動包含：

- 第 4 週：`typing_task_2`
- 第 5 週：`typing_task_3`
- 第 6 週：`typing_task_4`
- 第 7 週：`typing_task_5`
- 第 10 週：`typing_task_2`
- 第 12 週：`typing_task_5`
- 第 13 週：`typing_task_5`
- 第 14 週：`typing_task_5`
- 第 15 週：`typing_task_5`
- 第 16 週：`typing_task_5`

正式結算時，以成績設定檔中列入的 typing 活動為準。

目前上述正式 typing 活動全部納入。

### 關卡點數

中英打闖關採點數制。每一關的點數等於關卡序號：

```text
第 1 關 = 1 點
第 2 關 = 2 點
第 3 關 = 3 點
第 4 關 = 4 點
第 5 關 = 5 點
```

因此：

```text
5 關活動滿點 = 1 + 2 + 3 + 4 + 5 = 15 點
2 關活動滿點 = 1 + 2 = 3 點
```

通用公式：

```text
N 關活動滿點 = N * (N + 1) / 2
```

### 已通過關數

根據 `student_progress` 推算已通過關數：

```text
completed = true  -> 已通過關數 = 總關數
completed = false -> 已通過關數 = current_level - 1
沒有進度資料      -> 已通過關數 = 0
```

已通過關數必須限制在 `0` 到 `總關數` 之間，避免異常資料造成分數超出範圍。

### 單次活動點數

```text
單次活動已得點數 = 1 + 2 + ... + 已通過關數
```

通用公式：

```text
單次活動已得點數 = 已通過關數 * (已通過關數 + 1) / 2
```

例：某 5 關活動中，學生目前 `current_level = 4` 且 `completed = false`。

```text
已通過關數 = 4 - 1 = 3
已得點數 = 1 + 2 + 3 = 6
該活動滿點 = 15
```

### 總成績

```text
中英打闖關成績 = 所有納入打字活動的已得點數總和 / 所有納入打字活動的滿點總和 * 100
```

這個算法讓後面較難的關卡自然有較高權重，也能讓第 10 週這種短闖關依實際關卡數計分，而不被放大成和 5 關活動同等滿點。

### 未完成打字活動

結算日前：

- 可顯示目前累積點數
- 即時預覽可顯示「目前得分率」，但必須清楚標示不是正式結算分數

結算日後：

- 納入但沒有進度資料的活動以 0 點計算
- 納入但未完成的活動依已通過關數給點
- 該活動滿點仍計入分母

## 結算原則

匯出或期末整理時需先決定「納入活動清單」，再計算滿分。

不可直接用資料庫中學生已有的 row 反推滿分，否則未作答或未開始的學生會讓分母變小，成績被高估。

匯出計算流程：

1. 從成績設定檔取得本次結算納入的 quiz 與 typing 活動。
2. 對每位學生讀取這些活動對應的 `student_progress` row。
3. 資訊素養答題依答對題數總和除以總題數。
4. 中英打闖關依已得點數總和除以滿點總點數。
5. 兩項成績分開輸出，四捨五入規則由成績匯出功能另訂。

後台可即時依最新 `student_progress` 動態計算顯示，也可匯出 CSV / 試算表資料；不建立結算快照表，也不把計算後的分數回寫到 `student_progress` 或其他成績表。

後台顯示與匯出檔中的參考分數皆四捨五入到小數點後第 1 位，例如 `83.333...` 顯示為 `83.3`，`100` 顯示為 `100.0`。

## 實作注意事項

- quiz 活動判斷不可只依 `activity_key` 字串猜測，應以成績設定檔列入的活動為準。
- typing 活動總關數不可只從 `activity_key` 的數字推測，因為歷史命名不一定等於實際總關數。
- `completed = true` 的打字活動，已通過關數應視為總關數。
- `completed = false` 的打字活動，`current_level` 代表目前可挑戰的關卡，因此已通過關數是 `current_level - 1`。
- 異常資料需 clamp，避免已得點數小於 0 或大於該活動滿點。
- 後台若有顯示 typing 總關數，需與正式成績設定檔一致。
