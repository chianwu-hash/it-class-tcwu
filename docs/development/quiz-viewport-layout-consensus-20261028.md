# 答題頁：同屏閱讀與固定操作列設計共識

日期：2026-10-28；2026-10-29 更新：使用者已授權雙欄與固定操作列獨立整理、驗證後發布，排除半葉與努力花園。實作及驗收以 [獨立發布紀錄](quiz-workspace-release-20261029.md) 為準；以下保留原始設計討論及當時的待驗收項目。

## 使用者需求與已確認原因

學生送出答案後看不到「下一題」，因為解析和按鈕在視窗下方。目標是充分使用教室電腦的版面，一般題目、選項、結果與解析在同一畫面可讀，無須捲動尋找下一步；系統提示也應集中。

截圖呈現 navbar、重複品牌列、卷名／進度、葉片說明及最後一題提醒分別堆疊，題目約從畫面中段才開始。實際程式另有放大問題：

- `shared/quiz-student.css` 桌面 `.question` 設 `min-height:calc(100dvh - 172px)`；其他頁首與訊息仍在卡片外，總高自然超過視窗。
- `shared/quiz-server.mjs` 將 `role=status`、葉片狀態、關場提醒、完成提醒各自加入根容器；單題內接續排列材料、題目、選項、解析及操作列。
- 目前只有成功保存才提供下一題，最後一題先顯示結果再由學生開啟整卷回顧。這些既有行為必須保留。

## 同一次改版的版面目標

### 桌面

沿用共用導覽列，精簡重複品牌列；卷名、當前題號與進度改為緊湊的一列，長卷名仍能完整讀取。工作區高度依實際可見視窗扣除導覽、題目抬頭與底部列，不再由卡片另占整個視窗。

一般題採穩定約 60／40 雙欄：左為材料、題目和四個選項，右為答題結果與解析。送出前右欄只放「送出後，一起核對想法」等中性短句，不提供答案線索；送出確認後原地顯示對錯、小動畫、鼓勵語、正解與解析，不讓選項因左右重排而跳動。

```text
┌ 共用導覽：回上頁／努力樹／課程首頁／本人身分 ┐
│ 卷名                       第 3／10 題  ▰▰▱ │
├─────────────────────┬─────────────────────┤
│ 題目、圖片或材料       │ 這題的結果             │
│                     │ 小動畫＋鼓勵語          │
│ A 選項    B 選項      │ 正確答案               │
│ C 選項    D 選項      │ 解題說明、圖片或表格      │
├─────────────────────┴─────────────────────┤
│ 已儲存 ✓    訊息（2）    回看前題    下一題 →   │
└───────────────────────────────────────────┘
```

「送出／下一題／查看整份解析」在固定操作列的同一位置。這一列預留實際高度，不以覆蓋正文的浮動按鈕實現。次要的回看與更新狀態降權，但保持可發現及可操作。

### 長內容、手機與放大

- 一般短題在常見教室螢幕，以 100% 縮放為同屏完整呈現的驗收目標；**尚未實測，不保證所有題型零捲動**。
- 桌面雙欄如需捲動，只讓明確標示的內容面板捲動，避免再疊整頁及材料的多層捲動；捲動區可用鍵盤操作，有可見提示。
- 長材料或圖片選項使選項無法清楚呈現時，回退單欄自然長頁；不以縮小文字、裁圖或截斷解析硬塞。
- 大圖以可閱讀縮圖搭配既有原圖燈箱，燈箱層級高於操作列。
- 手機及高倍放大採自然單欄，題目與解析保持在同頁，**不用「題目／解析」頁籤**。底部主操作仍可見，預留安全區與鍵盤焦點空間。
- 全卷回顧保持自然長頁，不強制套入單題視窗工作區。

## 集中系統提示

操作列左側設「目前狀態」，旁邊可開啟本次訊息詳情。不再把每條訊息變成正文上方的新橫幅，也不為通知新增資料庫請求或本機進度儲存。

| 情境 | 直接顯示 | 詳情及動作 |
| --- | --- | --- |
| 正在儲存 | 正在儲存答案 | 防止重複送出，保持等待狀態 |
| 儲存失敗／尚未確認 | 尚未儲存，請重試 | 錯誤原因可讀，提供相同答案及相同 request_id 的重試；不顯示成功或下一題 |
| 儲存成功 | 已儲存 | 可前進；完成進度與末題說明合併進抬頭或適當主動作 |
| 答得太快 | 請看清題目和選項再作答 | 直接顯示本次尚未送出，不只藏在訊息詳情 |
| 本次閱讀時間資料不完整 | 本次不計葉片，作答已保留 | 用中性摘要與可展開原因，不阻擋回看或下一題 |
| 已關場 | 本場已結束，可回看已儲存題目 | 禁止新送答，保留已存紀錄可用的回看功能；不強行新增原本不允許的全卷揭答 |
| 一般完成提醒／不重複計葉原因 | 必要時簡短摘要或訊息數量 | 完整文字在同一訊息區展開 |
| 新得葉片 | 沿用慶祝及努力樹入口 | 動畫不擋按鈕、尊重減少動態設定，不要求等待動畫結束 |

同時有多種訊息時，優先呈現阻止新作答的錯誤及保存狀態；葉片等資訊不能覆蓋未保存警告。重要錯誤不自動消失、不只靠顏色區別。存檔狀態以單一 `aria-live` 區域播報，與結果及慶祝協調，避免重複播報同一事件。

## 實作順序及不變契約

固定操作列與精簡頁首先完成，再加入桌面雙欄，作為同次改版的驗收範圍。雙欄尺寸門檻依本機實測決定，不先寫死 Claude 第一輪建議的 1200×600。若某尺寸短題仍無法可讀呈現，採可用的回退方案並誠實記錄限制。

不得改動後端評分／揭答、Google 身分及名冊核對、本人資料隔離、切換帳號 generation、答案保存／冪等重送、閱讀防弊、葉片規則或媒體來源。保留標楷體、Andika、原生公式表格、圖片燈箱及十套動畫。

按鈕依既有狀態顯示：未答為送出，保存中為等待，未確認為同答案重試，當題保存後為下一題，最後題保存後為查看整份解析；最後題仍須先呈現當題結果，不自動跳去全卷。未符合揭答條件時不生成尚未開放的解析。送出後合理移動焦點到結果標題，避免強迫整頁跳到按鈕以下。

## 待實作後驗收

1. 1920×1080、1366×768 螢幕的實際瀏覽器內容高度（扣除工具列），390px 手機、200% 放大；確認下一步按鈕可見，無水平溢出或遮擋。
2. 短題、長材料、長選項、圖片／表格／公式、原版聽力與長解析；答對、答錯、無解析及延後揭答。
3. 第 1 題、一般題、最後題、全卷回顧；最後題對錯先顯示，之後才由學生開回顧。
4. 保存中、失敗、送達但回應遺失後相同 request_id 重送；未保存不出現下一題，重整可接回。
5. 快答警告、已關場可回看、切帳號清空舊題及訊息；不新增資格查詢／資料庫寫入。
6. 十套回饋動畫、得葉慶祝、努力樹連結、燈箱縮放與關閉；動畫不阻擋主操作。
7. 鍵盤 Tab、可見焦點、讀屏播報、內容區捲動、reduced-motion。
