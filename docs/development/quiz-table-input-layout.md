# 原位表格輸入的寬度與驗收

## 何時使用

原題表格移入既有輸入控制後，手機看不完整分數、輸入超出格線，或表格將整頁撐寬時，先量實際尺寸，不以保存成功代表介面通過。

## 已確認的原因

原表格的固定欄寬會壓縮控制。只補控制的最小寬度，控制仍可能跨到鄰格；改成自動表格後，Grid的內容最小寬度又可能撐開整頁。另在自動表格中使用含百分比的控制寬度，會引入循環尺寸計算，讓原生input預設寬度參與欄寬估算。

本次實測：外層可用323px，Grid自動欄曾達899px；補Grid收縮後，wrapper可留323px，但含百分比的控制仍使表格約855px。改為明確控制寬度後，同一題表格約380px，wrapper323px、頁面375px，原格與控制不再互相覆蓋。這些尺寸是特定隔離案例，不是所有題目的固定規格。

另一案例完整回顧仍有407px頁寬，逐層尺寸已正常。單獨實驗發現KaTeX的絕對定位`.katex-mathml`以body作為offsetParent，逃出表格捲動範圍。只讓原wrapper建立相對定位後，同頁寬回到375px；MathML與可見分數均保留。不能靠移除MathML或隱藏公式解決。

## 修正方法

1. 只對已核來源且實際含輸入控制的表格套用樣式。
2. Grid使用`minmax(0,1fr)`，直接內容子層`min-width:0`，避免內容寬度向外傳。
3. 原表格採自動欄寬，控制用明確且可成長的寬度，避免循環百分比；不以參考答案決定格寬。
4. 原wrapper限於可用寬度並`overflow-x:auto`、建立相對定位，讓公式的無障礙絕對定位內容留在捲動範圍。提供可聚焦且有名稱的捲動區域；核對文字可正常換行。

原理可參考[W3C Grid自動最小尺寸](https://www.w3.org/TR/css-grid-2/#min-size-auto)與[CSS尺寸中的循環百分比](https://www.w3.org/TR/css-sizing-3/#cyclic-percentage-contribution)。Claude提供的程式碼分析只是修正線索，仍須瀏覽器量測。

## 驗收

桌機、320／390px與文字放大，作答及完整回顧各檢查：控制在原cell內、input及cell內容未截斷、相鄰格不重疊。逐格聚焦後，所有`overflow:hidden`祖先不應橫向捲偏；頁面本身不橫向溢出。

對需要捲動的表格，實測鍵盤與觸控操作，確認能到最右格；直接設定`scrollLeft`只驗最右格可達，不能算手勢操作。保留原欄位ID、一次送出、冪等重試、重新整理接回及完整回顧。新規則若影響既有同類表格，至少抽驗一筆原已通過的來源。
