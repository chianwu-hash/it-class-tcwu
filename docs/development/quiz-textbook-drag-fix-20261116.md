# 課本拖曳被原生圖片拖放中斷

## 處理

使用者回報課本閱讀時，滑鼠拖曳出現圖片拖放影像，不能繼續平移。共享燈箱原本雖有 `draggable=false`、圖片不接滑鼠及禁止選取，缺少事件層的原生拖放攔截。若圖片重新成為可拖曳目標，瀏覽器可能啟動原生拖放而中斷 pointer 串流。

在實際燈箱以「圖片可接滑鼠且可原生拖曳」條件重現原版 `dragstart`；這是針對失效條件的可重複測試，沒有據此認定使用者電腦是哪個外掛或瀏覽器更新造成。

修正只在共用燈箱：左鍵 `mousedown.preventDefault()` 防止原生拖放與選取，`dragstart.preventDefault()` 補強，並以 CSS 禁止 WebKit 圖片拖曳及整個閱讀區選取。保留 pointer capture、既有平移／縮放邏輯；失去 capture 時結束追蹤，右鍵不開始平移。刻意不取消 mouse pointerdown，避免壓掉相容滑鼠事件而破壞雙擊縮放。

不修改課本、頁碼、教材授權、答案／作答紀錄、登入或資料庫。普通圖片燈箱原先的初始倍率／下限保持。重新生成四種課程共用入口及 CSS／資源版本。

## 驗證

- 9 項設定、翻頁排序與練功坊入口測試全過。
- 新實際瀏覽器回歸 24 檢查全過：1280／390 寬、一般題庫／考古卷，80% 與100% 真滑鼠平移、可拖曳圖片仍不啟動原生拖放、dragstart 被取消、右鍵不移動、失去 capture 不殘留拖曳、真雙擊放大、翻頁及重新開啟保留閱讀位置／原選答。
- 既有縮放回歸 83 檢查全過：20% 下限、80% 初始、100% 適合寬度、按鈕與滾輪、真滑鼠／可信任雙指縮放、79–80 完整拉頁、導覽與焦點、離開及登出清圖、普通圖片設定保持。
- 原版在同一可拖曳條件可重現原生 dragstart；修正版同條件為0且繼續平移。測試走本機合成帳號、合成教材及真控制器，不讀寫正式學生，不代表已在使用者當時的 Chrome 工作階段驗證。
