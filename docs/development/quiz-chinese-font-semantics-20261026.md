# 國語題庫：注音與國字的字型語意保留

2026-10-26，使用者先確認記錄規則，後續再授權盤點目前已入卷題目並修正。以下保留問題來源與規則，修正結果見末節。

## 已確認的問題

- 康軒三上國語第一課題目 `ECH1505002207`，書商分類為「選擇題-字音字形」。
- 原始 DOCX 中，題幹括號內的「妒」指定 `書法居中（注音一）`；選項「怒、路、妒、妨」指定一般 `書法家中楷體`。書商答案為原選項 3（妒），網頁打亂後字母可能不同。
- 此題考的是看注音選國字，題幹目標應呈現 `ㄉㄨˋ`，選項維持國字。只擷取底層文字會把題幹錯轉成「妒」，直接露出答案。
- 原檔：`automation/output/quiz/all-midterm-local/kang-g3-ch/source/ECH1505002207.docx`；資料列與字型已直接核對 `metadata.json`、DOCX `word/document.xml` 與 `word/fontTable.xml`。

## 後續轉換規則

1. 國語字型可能承載出題語意，不能一律當作外觀而捨棄。轉換時必須保留並檢查文字區段的字型、樣式及上下文，再判定是國字、注音，或國字附注音。
2. 分開辨識「看注音選國字」與「看國字選注音」；不可把題幹或選項全部換成同一種文字，也不可僅憑答案猜題意。
3. 不可把所有名稱含「注音」的字型一律轉成純注音。原題同時使用 `書法中楷（注音一）` 與 `書法居中（注音一）`，應分別核對字型實際呈現；未知字型與多音字列為待核對，不自動套讀音。
4. 確認純注音的區段應轉成標準注音文字與適當網頁排版，保留聲調；教學圖仍保留原圖，沿用文字／表格／公式原生呈現的既定模式。
5. 題幹、選項及書商解析都要檢查；答案仍以穩定選項 ID 對應，不能因選項打亂而改變正解。

### 讀音依據與轉換

- 從康軒原始 ISO 的 `SetupFont.exe` 靜態解出字型，未執行安裝程式、未安裝到 Windows、未將商用字型上傳網站。依字型字形建立接觸表，逐字核對本次使用的 39 個第一讀音字碼及「得」的第三讀音。解包過程參考 [binary-refinery 的 Setup Factory 解析與 PKWare 解壓實作](https://github.com/binref/refinery/blob/master/refinery/units/formats/archive/xtsf.py)。
- 已確認不能猜讀音的例子：字型中的「長」對應 `ㄓㄤˇ`、「為」對應 `ㄨㄟˋ`、「的」對應 `˙ㄉㄜ`，而 `書法居中（注音三）` 的「得」對應 `ㄉㄟˇ`。保留原錯誤讀音選項作為干擾項，不把每個選項都改成一般字典的正確讀音。
- 可維護轉換模組：`automation/lib/quiz_chinese_fonts.py`。僅轉換已核對純注音字型／字碼；未知字碼或讀音變體直接中止，不默默回退國字。`書法中楷（注音一）` 等國字附注音字型不會被錯轉為純注音。
- 本機既有 `native_docx_content.py` 已接入模組，在合併文字前轉換；兩份國語來源目錄與規劃資料也同步修正。原檔、修正前資料與逐欄對照另存本機受 Git 忽略的 `automation/output/quiz/all-midterm-local/review/chinese-font-audit/`。
