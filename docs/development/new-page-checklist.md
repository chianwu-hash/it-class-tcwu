## 1. Navbar

- [ ] 使用 `navbar.js`（不手刻 nav HTML）
- [ ] `navbar.js` 有版本字串，格式 `navbar.js?v=YYYYMMDD`，日期為開發當天
- [ ] 115 學年度新週頁放在對應學年度資料夾，例如 `grade3/115-1/weekXX.html`，不要新增到舊的 `grade3/weekXX.html`
- [ ] 根目錄 `index.html` 的主入口已指向目前學年度首頁，例如 `grade3/115-1/index.html`；舊學年度入口只放在封存/備查區
- [ ] 若 grade3 115-1 週頁面：確認 `grade3/115-1/navbar.js` 的 `activeWeeks` 陣列已加入這週的週碼
- [ ] 若 grade6 115-1 週頁面：確認對應學年度 navbar 的 `activeWeeks` 陣列已加入

## 2A. 三年級 Google 登入前：課堂身分卡分支（若適用）

- [ ] 此頁使用課堂身分卡取代 Google 登入；navbar 同一時間只顯示其中一種身分入口
- [ ] `initClassCardAuth({ courseId, mode: 'required' })` 已啟用，並明確標示「這不是 Google 登入」
- [ ] 課堂身分卡只用 localStorage 保存目前身分與 RPC 所需的臨時驗證資訊；任何活動進度不得寫入 localStorage
- [ ] 互動進度使用 `createClassCardProgress()` 寫入 `guest_progress`，不寫入 `student_progress`
- [ ] 正式保存前確認目前身分來源為 `rpc`；若瀏覽器仍保存舊 `sample-roster` 身分，而該學生已加入正式名冊，會重新驗證並升級，不能讓 navbar 看似已確認卻無法保存
- [ ] `initTypingChallenge()` 若用於此分支，已設定 `requireAuth: false` 與 `guestProgress`，並確認不會讀取背景 Google session
- [ ] 測驗 / 視窗練習 / 其他互動活動皆使用 `loadGuestProgress` / `saveGuestProgress`，未輸入課堂身分卡前不可作答或操作
- [ ] 教師後台可查詢與重設 `guest_progress`；重設後學生重新整理會回到未完成狀態
- [ ] 若此頁曾用 localStorage 暫存進度，已清除舊進度鍵，避免舊瀏覽器狀態誤導畫面
- [ ] **此頁不適用課堂身分卡分支** → 標記 N/A：`___`

## 完成標準

完成開發後，在 `http://localhost:3000`（或正式站）逐項確認：

- [ ] 一般 Google 登入頁：未登入時 navbar 顯示 Google 登入按鈕；點登入會跳轉 OAuth 並回到此頁；登入後 navbar 顯示 email，教師帳號出現後台按鈕

- [ ] 未確認身分且有測驗：只顯示鎖定區，不能看到或點選題目選項
- [ ] 未確認身分且有打字闖關：輸入框與檢查按鈕為 disabled，不能輸入或過關
