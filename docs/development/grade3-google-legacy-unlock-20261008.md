# 三年級第 02～05 週 Google 闖關覆核

2026-10-08。修正學生使用學校 Google 帳號後，第 03 週仍無法開始打字的問題。

## 原因與修正

- 第 03、04 週已接上可信 Google 身分及正式進度 RPC，但確認本人後只移除容器的 `inert`，沒有啟用 HTML 原先 `disabled` 的輸入框及檢查按鈕。無舊進度時尤其明顯；有進度時共用模組會恢復部分輸入框，但沒有 ID 的檢查按鈕仍停用。頁面身分控制器現在同時更新容器與控制項。
- 第 02 週 UI 原先依提示文字判斷是否可操作。Google 轉換改寫了首次登入提示，造成辨識失效；初始鎖定也會停用「下一關」按鈕。第 02 週與快手投遞改用明確的進度讀取完成狀態，成功後恢復控制項，讀取失敗則保持鎖定。
- 快手投遞的先修成果讀取補上錯誤處理與 `finally`；失敗會顯示原因、保留鎖定並開放重新確認，不再留下未處理例外或永遠停用重試按鈕。
- 更新第 02、03、04 週及投遞頁的 JS 快取版本。共用 Google 身分、資料庫、努力樹獎勵及舊成果轉換規則未變更。

## 驗證方式

`automation/tests/grade3-google-legacy-browser.cjs` 使用已登記 AI 工作瀏覽器、隔離瀏覽器 context 與合成 Google 身分／RPC，不讀寫正式學生紀錄。

- 五組打字共 27 關，使用實際輸入框與檢查按鈕；包含無既有進度、答錯不儲存、儲存失敗不解鎖、重試、重新整理接續、全部完成及完成後重新載入。
- 每組確認寫入正確週次與活動，不呼叫舊身分卡／匿名進度 API；再開努力樹驗證葉子與花。
- 第 02、03、04、05 週及快手投遞均驗證未登入、身分接回失敗、進度讀取失敗時不可開始、不寫入；投遞先修讀取失敗可重新確認。
- 第 02 週五題坐姿答題、五步視窗操作、第 03 週五題安全測驗實際完成、重新載入及努力樹驗證。
- `node automation/tests/grade3-google-transition.test.mjs` 的兩組實際 PostgreSQL／PGlite 測試通過，涵蓋可信身分、RLS、歷史保留、原子接回、重試、成果不倒退及教師重設。

這次驗證 Google 登入後的課程操作與資料庫契約；不把合成身分測試宣稱為重新完成正式 Google OAuth。正式學生既有成果不清除、不補造。
