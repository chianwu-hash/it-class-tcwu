## 1. 批次的單位與啟動順序

### 效率接續共識（2026-11-21）

總帳只由程式彙整既有收據並增量更新，缺證據記 unknown，不人工填通過，也不把未連結的歷史證據當失效。`automation/build-quiz-conversion-ledger.py` 先核來源身分、候選 SHA 與收據參照；候選契約標籤不代替原題角色分類，隔離資料、行為重用、媒體、正式 OAuth 與啟用分欄記錄。輸出留 repo 外。優先從已驗候選找完整可交付者，再批次補相同群缺口，不只追求新增候選數。

同規則／角色／adapter 與行為契約一次處理整組可用來源，不按兩三題開新分支；行為指紋只包含真正受影響的程式與契約依賴，來源 guard／數字變更另走資料檢查。媒體按 hash 去重，已就緒群合成一份 release manifest，避免每幾題發布一次。每批一份固定格式、原則30行內的公開收據，交接只加一行連結；詳細證據留私有，不為整理舊長文阻塞主線。

資料檢查失敗率超過10%或同因第三次出現時，先停受影響群診斷／一般化；其他群繼續，不自動找 Claude。共用呈現／序列化／判分／函式變更獨立處理；授權或揭答隔離失敗阻擋相關發布，週剩餘小於等於15%才停止整個長線。每批分記題數、資料處理時間與發布成本。缺介面與未分類者保留原因及待辦，不因題數少刪減範圍；新 adapter 集中補一次並記涵蓋數與估計／實際成本。Claude 僅限未解語意／答案疑義或高影響新共用契約，不做例行二審。

以「既有轉換規則＋作答契約版本＋呈現分支」分組，不以來源 ID、書商名稱或每兩三題作一個新介面。不同科目、數字、字詞、圖片或教材頁，若未改變行為，就沿同一規則批次處理。書商題型名稱只作線索，須同讀原題、原題型及已固定來源要求；不能由答案反推介面。

1. 讀取來源／固定複核、不可變版本、既有轉換器及本索引；核實目標入口實際具備的能力。
2. 來源要求已明確且符合規則者，直接程式擷取、轉換、產生解析／教材綁定及資料收據。已有固定解析、重點與配題就沿用，不為換封裝重新生成或送模型。
3. 逐筆跑下節的資料檢查，將失敗來源與具體原因放入例外佇列。其餘來源持續批次轉化。
4. 依驗收證據鍵查找可沿用的代表題收據。有效就沿用；缺少時只驗真正新增的呈現分支，不重做已接受的試用。
5. 一個完整批次交付候選、逐筆資料結果、沿用的介面收據及例外清單。批次大小由資源／API 限制決定；拆成多次傳送不會重置介面驗收。

「試用已接受」「正式程式具備」「來源資料已通過」「已發布」分開記錄。八種試用已接受其操作方向，不代表新版 drawing 契約已正式接線。待接線類集中補 adapter 一次，接好才批次轉化；不能以空白畫板、普通文字欄或計算紙冒充專用作答介面。

## 3. 每筆都做的資料檢查（以程式執行）

這些檢查不因沿用介面而省略，也不需要每筆找 Claude。結果須來自實際檢查輸出，不能手填一串 true 代替檢查。

- 原件／題型／固定複核版本及 SHA；題幹、共同材料、選項、必要樣式、圖與音訊完整。
- 每個原作答位置的角色、欄位 ID、型別、單位與答案映射；原輸入、人工過程及教師例解的位置不可混淆。
- 現行 validator、來源 guard／真實 copy_self 綁定、完整欄位覆蓋與封裝限制。新來源需重算自己的綁定指紋，不沿用其他題的 source guard。
- 原鍵保持；獨立可計算者用程式核算，等價答案與配對照現行契約，開放例答不得偽裝成唯一正解。無法由可靠資料定案才升級疑義。
- 固定解析、學習重點、教材版本／頁碼及配題狀態。已有可靠複核就沿用；無可靠對照如實標明，不硬配、不重做整題 AI 分析。
- 新媒體逐資產核 bytes／SHA／MIME／私有映射／正式授權供圖；既有同 hash 且供圖契約未變者沿用，毋須重新上傳或重跑登錄。
- 批次匯入的逐筆等值讀回、不可變版本及保護資料摘要。新增內容不得沿用別份候選 SHA 的資料收據。

來源文字、數字或圖不同，會產生新的**資料收據**；這不會自動使相同介面的**行為收據**失效。

選答依學生實際要完成的作答判定。只要學生從固定選項選一個答案，就用同一種單選；書商的圈選、打勾、貼圖或圖案規律等名目沿用同一選擇題流程。多欄圈選、是非、符號和比較須逐欄綁定原位置。單選比對原選項次序、顯示內容與原鍵 ID。原題有明示勾選指示及選項標籤時，單列的空勾選框或完整選項圖片旁的空勾選框可按紙本操作提示處理。題意中的方框必須保留。選項圖的雜湊不同時，核對候選檔案雜湊及同尺寸完整 RGBA 像素後才能對帳，圖片順序仍須一致。純文字且有完整連續標籤的最重／最輕圈選，教師鍵、固定複核與換算結果一致才建立候選。共用程式見 `automation/lib/quiz_choice_source_binding.py`。

教師原答案以圖表示時，先按原卷順序列出選項。原答案圖的 SHA 若唯一吻合一個原選項，以該位置綁定正解；原卷規律可獨立驗算時一併核對。若與舊複核位置不同，保留原紀錄，另附原件 SHA、選項位置與驗算作為更正證據。圖像有裁切、翻轉、重複，或答案檔同時含多個選項時，須有足以區分正解位置的原卷證據才建立候選。

原題將單選選項合在同一張圖時，依原卷的編號或明示位置裁成各自獨立的選項圖。裁掉編號、紙本勾選框及分隔線，保留物件、刻度和解題所需的圖形資料。選項上的重量或名稱若從圖中分離，另以原值附在同一選項下；題幹用的共用圖沿原位置保留。逐題記錄原圖 SHA、裁切範圍、原卷次序及教師鍵到選項 ID 的對照。位置或答案對應未定時列例外。驗收時用原卷順序比對；正式自組卷預設會亂序，要求學生看到固定原序的批次，須另驗組卷時的選項順序。

原卷只要求勾選一個答案時，直接按單選批次處理。紙本勾記以原標號或原選項文字對應正解，例如教師答案「②ˇ」要與固定複核的「②方框填 v」核對位置，再按原序轉成選項 ID。有圖的題目沿用同一規則。原卷放在選項內的文字和圖留在該選項，位於選項區之前的共用圖依原圖文順序留在題幹。可獨立驗算的數值須與原鍵相符。教師答案與複核位置不同、看不出勾選框或圖片的歸屬，或須同時標不同符號的題目另行分流。

數值與單位的原鍵依完整片段擷取。明示單位、公斤／公克、時／分保留原順序，同單位等值分數保留原寫法及替代值。多小題的「答」行須逐段綁定原題可見標號。答案圖、原圖專有標號、異形表與巢狀結構須先核對原位置；跨單位或成組替代值須取得確定的單位與配對映射。教師鍵與固定複核不一致時列出差異。總帳可用 `--isolated-equivalent-readback` 連結相同 schema、函式及候選 SHA 的隔離讀回，與正式供圖、行為重用及 OAuth 各自記錄。

## 4. 代表題驗收與證據重用

### 證據鍵

沿用必須能核對：`rule_id + rule_version + adapter/呈現分支 + 相關 JS/CSS 指紋 + 序列化/後端契約版本 + 已驗入口 + 螢幕級距`。記原收據路徑、代表來源、實際測過的操作及證據時間。不同題幹的 candidate SHA 不放入共用行為鍵；另以逐題資料收據連結來源與該鍵。

實際分支由作答角色及工具能力決定，不因來源 ID、每批起訖或不同書商重新命名。guard 更新只證明此來源可套模板；不能把 guard 當行為證據，也不能因每題 guard 不同就重跑相同全流程。

### 何時驗什麼

既有題庫規則新增來源時，正式網站的人工驗收每批抽 **5%**，依來源題數無條件進位，至少 1 題。各題型採同一比例，依整批題數計算即可。樣本優先涵蓋這批較容易出現顯示或操作問題的題面，再抽其餘題目。用專用帳號實測樣本的顯示、送答、判分及重新開啟後的回顧。發現問題時記錄並視影響範圍調整抽驗。第 3 節的逐題程式檢查、批次等值讀回及正式資料庫授權流程照常執行。

| 變更／情況 | 必須驗 | 可以沿用，不得例行重跑 |
| --- | --- | --- |
| 規則、adapter、呈現分支、前後端契約都相同，僅新增同類來源 | 全筆資料檢查、批次等值讀回；整卷／整科發布時依已有關卡做入口 smoke | 相同代表題的完整保存、重試、接回、回顧及 Claude 意見；不為每批再做 5–10 題小樣。 |
| 同規則的來源出現新的長度、圖量、單位或題組邊界，超出已驗範圍 | 只驗新增邊界的版面／對位，建立可沿用的分支收據 | 未受影響的儲存、權限、葉片或所有其他題型全套。 |
| 共用 renderer、工具互動或相關 CSS 改變 | 跑受影響規則／分支的既有代表案例與必要邊界 | 未受影響模組的逐題全套；不重送全部內容給模型。 |
| 序列化、判分、揭答、授權、DB 函式或來源 adapter 改變 | 受影響契約的保存、冪等、接回、揭答前後、跨人拒絕、個人／夥伴／完整回顧等完整回歸 | 無關內容的再解題、未變媒體的再上傳。SQL 與發布規則照舊。 |
| 內容／答案／解析換版 | 新 SHA 的資料核對及相應判分／揭答差異；UI 文字若超出既驗邊界才加局部畫面驗證 | 不能以「換版」為由重做沒有變動的共用互動全套。 |

一個新分支通常一題代表；若一題無法包含明確不同的分支，才加最少代表案例並註明缺哪個分支。新行為首次完整驗收覆蓋原題→操作→同次保存→重試／重載→個人／夥伴回顧及必要揭答隔離；桌機／手機及其他已知風險級距只對代表案例驗。表格、長字、讀數免過程、混合文字等已驗分支，不因下一題又有相同情況而重驗。

正式 OAuth、隔離真 SQL、真人帳號、實體手機與本機試用各自標範圍，不互相冒充。既有發布安全關卡、整科門檻及必要正式 smoke 不取消，但每次 smoke 也不重做所有來源的完整 UI。

## 5. 真正例外與 Claude 使用界線

| 例外代碼 | 情況 | 處理 |
| --- | --- | --- |
| SOURCE_AMBIGUOUS | 原件缺字、圖文邊界／標記／作答角色仍無法確定 | 先查原件，整理最小未解範圍；需要語意判斷才請 Claude。 |
| ANSWER_CONFLICT | 原鍵、獨立解題或可靠資料矛盾，等價答案範圍不能定案 | 保留原鍵，集中同一爭點與相關原頁供獨立複核；實質分歧才用 AGY。 |
| CONTRACT_GAP | 已定案操作尚無 adapter，或原題確有未支援的新行為／保存要求 | 集中補共用分支一次；新契約才做針對性程式複核與完整代表驗收，不逐題補丁。 |
| DATA_CHECK_FAILED | 格數／ID／SHA／範圍／欄位／配頁／媒體資料檢查失敗 | 程式診斷及來源核對，修完重驗受影響資料；不自動找 Claude。 |
| EVIDENCE_INVALID | 找不到可沿用收據或行為鍵已變 | 補缺少的代表驗證；不等同於題意有疑義，不自動找 Claude。 |
| MEDIA_PENDING | 新素材未完成私有鏈、格式或授權驗證 | 依既有媒體流程逐資產補齊；不讓 Claude 重新解題或重審 renderer。 |

Claude **不是固定生產步驟，也不是發布前固定再審一輪**。新共用契約的高影響程式審查或未解來源／答案疑義，才集中送一次最小證據包，明列問題、讀取範圍、定案條件與已知限制。純標籤、頁碼、固定規則下的資料修正，Codex 依來源及程式檢查處理。若先前意見已解決且沒有新爭點，記採納／不採納理由即可，不為取得「二審無問題」反覆送審。

一次例外解除後，將一般化規則、適用條件及代表證據回填索引／adapter，讓後續同類來源走批次，不再把相同原因列成新例外。發布可用與否仍以實際證據判斷，不用模型多數票。

## 6. 批次交付與停止條件
