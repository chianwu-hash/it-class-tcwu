# 我的錯題：本人錯題記錄與回顧

日期：2026-10-27。使用者授權先實作錯題記錄與整理，讓學生回看答錯題目及解析；相似卷維持規劃。

## 功能契約

- 入口：三／六年級原 `quiz-library.html` 的「我的錯題」，亦可使用同頁 `#wrong` 連結；保留原 navbar、Google 登入與年級分流。
- 資料：直接唯讀整理既有 Supabase `quiz_answers`，不複製答案、不新增錯題進度表、不使用 localStorage。舊作答會自動納入，新送出的錯答在開放解析後可按「更新錯題」讀取。
- 整理：科目、單元篩選；以作答時間由新到舊，每頁20筆。這是本人記錄清單，沒有分數排名。
- 回顧：共用材料、題文、原選項順序、當時選答、正確答案及解析；選擇題依 option ID 標示，不把亂序後字母當答案識別。簡答題顯示當時輸入與可接受答案。
- 呈現：沿用 `renderContent` 的原生文字、公式、注音、表格及原圖。國語楷體、英語Andika；原圖與解析圖的燈箱80%起始、可縮小、開啟時重新授權。學生提示不用「書商」。
- 保留單元卷、作答、揭答、動畫與登入行為；回看不送答、不建立 attempt、不將看過標為精熟。

## 後端

獨立新增 `supabase/quiz-wrong-questions.sql`，只建立 security-definer RPC `quiz_wrong_questions(jsonb)`，固定 `search_path=''`、撤除 public／anon 執行權，僅 authenticated 可執行。未修改原 `quiz_action`、RLS 或資料表。

先由原 `library_sessions` 核對登入、教師／學生及名冊年級。候選紀錄限定 `auth.uid()` 本人、目前仍有權進入的場次、錯答且已達原場次揭答條件；整卷揭答須整卷完成，即時揭答仍須整個共用題組完成。正確題、未答題及尚未揭答錯答連統計數字也不回傳。

清單只回傳題目預覽與編目、時間、識別資料，不包含答案與解析。單題明細再重用 `quiz_action('resume')` 的本人及揭答投影，只取指定錯題，不回傳其他題目的秘密。媒體沿用原 `quiz_media_access` 與正式Drive＋Cloudflare票證，沒有新建讀圖權限。

前端同一時間只讀取一筆明細，換人／登出時清空清單及明細，忽略前一身分的晚到回應。單元卷請求維持原路徑，只有新增動作導向新RPC。

## 驗收

- 新增兩組真實候選SQL測試：本人及跨帳號隔離、匿名拒絕、名冊撤除、題組與整卷揭答、固定選項順序、關場回顧、唯讀不改答案、教師本人試答、21筆分頁、科目單元篩選、異常參數。
- 原11組測驗測試及既有11組媒體／正式簽票測試通過，共24組。
- 正式Supabase已安裝此唯讀RPC；安裝前後原答案內容雜湊及筆數、attempt筆數完全一致。部署程式為 `automation/quiz-wrong-questions-deploy.mjs`，先核對既有專案再執行單一SQL。
- 本機使用真實測試學生的既存紀錄：單元篩選、三題回顧、正誤標示、表格、解析圖片、燈箱80%→70%、重整重新讀雲端、390px與他人attempt拒絕通過；沒有join／submit請求，12次Worker圖片、Supabase圖片0、頁面錯誤0。
- 初始兩次清單讀取曾顯示通用服務錯誤；後續直接RPC、同一request模組及頁面追蹤均200，完整流程再驗通過。初始原因未獲證實，不宣稱已定位為schema快取或網路問題；介面保留「更新錯題」重試，未放寬權限。
- 首次正式頁面驗收時，已開啟分頁仍持有舊的 API 模組（實際函式內容不含新RPC，且頁面沒有新錯題區）。同網址含錨點的導航沒有保證換掉整份文件；已為選卷入口及新API依賴加版本識別，驗收明確整頁重新載入。此證據只確認正式分頁的舊程式狀態，不倒推所有本機初始失敗均為相同原因。
- 證據於ignored `automation/output/quiz/wrong-questions/`，不提交學生資料、原題文件或短效票證。正式頁面驗收完成後另補紀錄。
