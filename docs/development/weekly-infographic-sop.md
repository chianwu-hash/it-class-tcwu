# 三、六年級每週資訊圖卡

2026-11-11 使用者定案：之後三年級、六年級每一個新製作的正式上課週頁，都要有該週資訊圖卡；三年級第11週這次一併補做。沿用六年級已走通的產製／驗收流程，兩年級各自保持原有視覺，不把六年級版型直接套給三年級。

## 適用與完成標準

- 有正式上課週頁，至少有一張當週教學重點／操作流程總覽。不是選配，也不因教案未提、已有文字任務卡或本週沒有新增圖卡需求而省略。
- 沒有上課且未建立週頁才可N/A；只做不涉及內容的舊頁修補不要求一次回補所有歷史週。使用者另指定例外時記錄週次與原因，不自行豁免。
- 第11週三年級補做，其他過往缺圖週不自動擴大回補；之後新週依此執行。
- 圖卡是課堂閱讀／投影輔助，不能替代網頁可讀文字、操作練習、真實按鈕、登入與進度保存。圖卡不列未授權的任務、不捏造時間／最低標準／獎勵。

## 固定風格各自沿用

- 三年級：[固定視覺風格](grade3-visual-style.md)。圖卡參考三年級第01週正式滑鼠／教室規則圖：年幼兒童、清楚可愛卡通、白底、藍綠／天藍、大字與明確步驟，黃橘作重點；不變成六年級紫色水彩版。
- 六年級：[固定視覺風格](grade6-visual-style.md)。圖卡參考同學期第09／10週正式圖：水彩筆觸、深藍粗圓字、紫／藍綠／橘／天藍分區、高年級兒童及白底圓角卡。
- 生圖前目視同年級參考圖，實際附上參考圖並核對上傳成功。只沿用風格，不複製舊週內容、班級示例或時間。

## 標準流程

1. 教案定稿後整理學生可採取的動作，原則一張3～4個重點、短句大字；保留本週重要按鍵／操作方向、必要備援及鼓勵語。先核對文案與現行頁面一致，再生成。
2. 依 `skills/chatgpt-image-workflow/SKILL.md` 與 `docs/image-and-preview-card-sop.md` 使用已登入的ChatGPT工作瀏覽器及CDP wrapper；UTF-8 prompt檔、精確分頁／租約、可見帳號核對、圖片模式與參考附件驗證。使用共用啟動器回傳的端點，不照舊例硬寫port。等待中的同一請求不得重送。
3. 原圖／metadata先存ignored證據目錄；生圖與下載成功分別確認。逐字檢查繁體中文、按鍵名稱、左右／流程、圖文一致、人物／手部、版面及與同年級風格連續性，錯誤要修正後再使用。不把仍在生成、參考圖或失敗產物當正式圖。
4. 以專案壓圖工具輸出1920×1080 WebP q80；不裁掉重要內容。正式資產置於對應學期 `gradeX/115-1/images/weekXX/`，原始大PNG、metadata與重複草稿不提交。
5. 上傳正確Cloudinary帳戶，採學期／年級／週次可辨識的新public ID，不覆蓋舊週。回讀HTTP狀態、圖片尺寸及SHA-256，與本機正式檔一致；憑證不得進repo／前端。
6. 在週頁放置「本週任務圖卡／本週重點圖卡」，img與燈箱連結使用同一正式WebP網址，具尺寸及涵蓋重點的alt；保留同內容的可讀文字。使用 `shared/image-lightbox.js`／`.css` 的同頁燈箱，不以另開圖片分頁取代，且初始化獨立於可能失敗的身分／進度讀取。
7. 1280／390實際驗圖卡載入、畫面不溢出、燈箱開啟／縮放百分比／滾輪／真實pointer拖曳／雙擊／手機雙指／重設／置中／關閉、捲動及焦點恢復、再開100%；回歸原頁受影響操作。缺少的人工裝置驗證明示，不以class或合成單一事件冒充完整手勢。
8. 契約記錄prompt、同年級參考、產物／壓縮尺寸與位元組、正式URL／雜湊、圖文審查、桌手機截圖與驗證限制；按main／PR／發布腳本流程，正式讀回後存收據並封存清理。

若原圖不符、Cloudinary未成功或燈箱未驗完，屬未完成項，不以「本週無圖卡需求」改標N/A。使用者已核定內容與本次自行驗收後發布的範圍時，完成品質驗收即可往下走，不重新要求同一項授權；另有明確要求人工審圖的案件照該案指示。

## 共用工作瀏覽器的可重用入口

外層 `ai-browser` 已持有租約並註冊worker時，舊image-batch CLI的獨立BrowserStore可能誤判租約失效。此時用 `automation/weekly-infographic-image.cjs` 呼叫同一套公開生圖函式，仍經共用 `run-background.cjs --lease-id <回傳值> --target-id <回傳值>`，不另建租約、不改profile／端點、不跳過可見帳號／圖片模式／參考附件／送出／生成／下載驗證。

內層參數：`--prompt-file <UTF-8檔> --reference-image <同年級參考圖> --output-dir <ignored輸出> --meta <ignored JSON> --expected-account <已核對的可見帳號名稱>`。參考圖可重複指定。相鄰workflow／cdp-tools為預設套件來源，特殊安裝用 `CHATGPT_IMAGE_WORKFLOW_ROOT`／`CDP_SAFE_CLIENT_PATH` 明確設定；CDP路由仍只讀啟動器環境，不寫死port。這個入口由第11週已成功執行的局部driver整理而成；換帳號／介面更新時先核對，不以舊驗收冒稱新流程成功。
