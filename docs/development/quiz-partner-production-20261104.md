# 夥伴練功正式整合與驗證

使用者授權現有名冊學生以邀請碼組成 2～4 人小隊，紀念直接計入原努力樹。主工作區不改檔；修改經 PR 進 main，正式發布只用 release-from-main.mjs。

## 功能與資料契約

- 沿用學校 Google 登入與 115 學年名冊，使用目前網站支援的三、四、六、九年級；教師與非名冊帳號不開放。老師卷沿用場次的班級開放範圍，考古卷沿用年級與啟用狀態。
- 2～4 人、人數到齊且全員準備後，任一成員可出發。題數差至多一題，主題人物不影響權重。每人只送自己的答案；請教、提示、聊天與標記留在同一營地。
- 全組每題先嘗試，再共同回顧；全員回顧後收進紀錄冊。以每題最後一次作答計 60%，開放自我核對欄位必須完成，但不列入自動判分分母。訂正補達時自動領取。
- 一般題組限 10／20 題，每人分別一／兩片紀念葉；完整考古卷每人一朵紀念花。同內容與相同排序後成員集合只領一次，換成員可再計。換房、隊名、加入順序不增加獎勵。
- 合作獎勵保留在權威 `partner_pilot.awards` 一筆全組紀錄，由 `quiz_rewards.partner` 與 `garden_growth` 直接彙入原努力樹。不是另外的測試樹；不偽造個人作答或把全葉投入舊半葉配對。
- ID 固定為 `course:00:partner_<award UUID>_<n>:quiz-leaf:1` 或 `:flower:1`。花葉可回到該次共同紀錄冊。原花葉順序、半葉、成長基準與已讀時間保留。
- 出發後凍結名單；離線儲存後可由同帳號接續。當天無法回來者的舊紀錄保留，在場者另組隊重新練，不轉移作答或代答。
- 正常題源改版，已出發房沿用固定副本；明確關閉／撤回則停止新作答與新領取，保留歷史與已獲紀念。新班級的同版本場次在 catalog/create 時補建連結。

## 題庫範圍與維護限制

本次沿用已匯入的固定題庫／考古題副本與既有媒體授權，沒有把課本、真實題目、學生資料或憑證提交公開 repo。新的題目版本仍須經原有內容匯入與審核流程產生新合作副本；不會自行從未審核來源生成題目。尚無可用合作副本的指定卷，入口明確說明，不會悄悄改選別卷。

`supabase/quiz-partner-schema.sql` 僅供全新環境建立舊試辦私有表，不可重跑在現有庫。現有正式庫只執行一次 `quiz-partner-production.sql`，不要另跑 policy fragment。函式快照必須在遷移後重新匯出並完成 live check。

## 發布順序與回復

1. 實作與測試 PR 合入 main。
2. 從 main 取 SQL，在正式庫先用交易回滾驗證，再套用；遷移會先把夥伴功能設為關閉，不動原個人練習。
3. 執行 `db-schema-snapshot.mjs` 與 `db-snapshot-check.mjs --live`，快照經 PR 進 main。
4. 新建乾淨 main checkout，發布腳本取得鎖，start → deploy → 完整樹比較 ok → promote；正式部署 ID 有變即中止。
5. 驗證對應前端後啟用 `partner_pilot.settings.enabled`。若夥伴功能出問題，可先關閉此旗標；原個人功能與已獲合作紀念仍保留，不刪除學生紀錄。
6. 發布腳本的 handoffRow 經 PR 登記。未通過與未執行驗證要明列，不宣稱已完成學生多機測試。
