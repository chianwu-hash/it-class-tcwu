## 本輪題型試用定案與長線接續（2026-11-20）

- **原圖單選（2026-11-21）**：單一選答位置保持原生single，保留完整原圖、原選項與順序；顯示層僅將重複圖庫移到選答卡。點圖選答與獨立放大分開，沒有原編號就不虛構字母，答案摘要也一併遵守。共同倍率須在揭答／錯答及整份、小隊回顧後重新量測，不能只量作答前；圖卡縮排或核對文字不得改變各圖的相對尺度。原「選最重」等要求在回顧仍須可見；延後載入的觀察元素必須有實體版面盒。詳[兩原來源隔離證據](quiz-image-choices-20261121.md)。

- **最重／最輕標記與留白（2026-11-21）**：按原卷保留每個比較項目，只在指定最重／最輕處標原符號，其餘保留未標記狀態；不要求每格硬填符號。數位「留白」是清除／未標記操作，初始不能預選；首次學生標記後僅將其餘未標記狀態帶入封包，不代判極值，不自動送答。若固定複核只列兩個邏輯角色，須另記其與全部原實體括號及留空限制的映射，不能偷改位置數或漏掉多標／漏標的判分。

- **原圖符號判斷補充（2026-11-21）**：原題要求打ˇ、畫○或打╳時，保留原符號與順序，不自動改成「正確／不正確」。每個圖塊就近放原作答控制；天平須保留完整傾斜關係，同一面板的比較圖保持相同像素倍率，完整原圖仍可放大。裁切僅為固定原圖的顯示範圍，不重畫題意或另生答案圖；驗收須捲到實際可見圖塊，確認完整回顧中的每張圖確實載入，不能只檢查第一張或只憑全頁截圖。

- 使用者已接受八種介面各一題代表：算式與過程、直式、方格作圖、圓與扇形、原圖塗色、長度／角度量測、圖表繪製、實驗／觀察紀錄。第7種保留本次描點與連線版本。這是**本機隔離試用接受**，不是所有科目、來源或正式入口已完整涵蓋；不再以91筆來源當91種介面，也不重做已接受的小樣。
- 本輪八類專用新介面尚待正式來源adapter整合；既有正式算式／直式保存、open sketch及考古manual／annotation各沿自己的現行契約。新增v2 drawing只在隔離資料庫驗證，`quiz-original-drawing.sql`尚未取得正式套用核准，不能沿用PR305或更早的SQL核准。需要新契約的來源標為候選／待接線，不將普通文字、空白畫板或本機保存冒充正式支援。
- 長線從最新來源與正式收據接續。PR305的算式／直式SQL及前端已正式發布，不再依舊私有狀態的「等待核准」重跑。三年級數學28筆接續候選另於下列驗收文件記錄；六年級既定已完成範圍不重匯。見[本次Claude檢核、修正與接續證據](quiz-conversion-sop-review-20261120.md)。

## 改錯題的指示與欄位（2026-11-18）

- 先核 NAS 原題、教師鍵及出版題型名稱；單題 Word 可能只有句子和括號，「改錯字／短文改錯」要求藏在原題型標頭。轉化後必須明說要找錯字、填入**改正後的字**，多欄另交代原件已確認的順序；不得只剩「第1格」和通用填答提示。
- 程式優先：`audit-correction-instructions.mjs` 依來源 ID、DOCX SHA、出版類型、原鍵與欄位順序建立顯示指紋清冊；未知來源、鍵數／順序不合或內容換版先退回，不能只靠括號、句子看起來有錯字或答案內容推斷題型。既有線上勘誤須另附原鍵／採認依據，不把它覆寫成官方原鍵。
- 原句的故意錯字是題目的一部分，**不得自動校正、提示位置、擴增改錯項目或據語感改答案**。欄名用「正確的字」「第1個正確的字」；舊卷有段落／小題定位時保留，已有清楚指示不重複加寫。選擇題、造句、語意題及其他科目的計算訂正不套國語改錯字規則。
- 用 `quiz-correction-presentation.mjs` 分開來源留存與學生呈現；一般題保留原題／欄位 ID、型別、正解、版本、已答封包，舊卷保留原段落與欄位對應。不得新增送出／確認階段、不換外層介面、不整庫送 AI。
- 驗收個人練習、整份回顧、夥伴練功與舊卷的桌手機，包含未答、錯答、保存接回、原欄位封包及原媒體。各科與歷史版本均掃描；原件與模擬測試、正式唯讀檢查分開記錄，不把隔離替身稱為正式學生寫入。詳[修正與驗收](quiz-correction-instructions-20261118.md)。

## 排序題共用卡片規則（2026-11-18）

已確認的9題 `fields/sequence` 使用共用排序卡片，手機保留上移／下移及鍵盤替代操作。題目、欄位與選項ID陣列保持，沿用原一次送出，不新增內層提交或第二次確認。初始卡片不是作答，不能自動填答或用預設正確順序；已保存順序必須原樣讀回。送出／回顧後只讀，位置核對不能取代原整組判分。

紙本選項清單、空格與代號只有在原來源完整對上卡片後才能清理，保留原件與固定版本；時間軸、圖表與圖片仍由原圖文渲染器呈現。解析不得引用會混淆目前位置的原代號，依原選項ID改用內容引用。未知來源不只靠「排序」字樣改型，新增來源須另核圖文、判分及對照。

驗收必含個人練習、整份回顧、夥伴練功／共同回顧的桌手機與既有錯序讀回；確認拖曳、上移下移、未操作不送答、原封包一次送出、原圖、pending鎖定、Esc取消與換題清理。不把本機替身稱為正式學生保存。詳[共用契約、來源與驗收](quiz-sequence-cards-20261118.md)。

> **輸入工具驗收（2026-11-18）**：注音／標點／數學符號使用共用浮動鍵盤，不複製內嵌鍵盤或新增送答流程。工具間留間距，浮層須有關閉鈕、標示目標答案格、避開送出列且不遮住輸入格；桌手機同驗切換、收合、選取替換與原封包。保留原外層與既有答案。詳[浮動鍵盤契約](quiz-floating-keyboard-20261118.md)。

浮動鍵盤的預設大小須容納完整按鍵，逐一確認聲調與刪除鍵可見、內容無水平／垂直溢出；不能只驗外框在視窗內、只隱藏捲軸或用固定高度截斷最後一排。至少核桌機、一般手機與窄版手機，並確認放大鍵盤後仍不遮住目標答案格與送出列。

本文件規範接續、帳號、資料取得、複核、發布及局部阻塞時的執行方式；搭配 `past-exam-playbook.md` 的製作／品質規範，不取代目前 schema、登入守衛或發布規則。個別任務的最新使用者指示優先。帳號、目標資料夾 ID、實際掛載及批次狀態放私有交接附錄，不提交公開 repo。

題型必須按實際操作意義判斷，不能只看書商類別或V／X字形。例如V標最多、X標最少是兩位置雙選，不是是非或一般多選；須保存兩角色、原選項及一次送出，另以原鍵、固定複核與獨立計算一致驗收。詳見[餘數雙選案例與拒絕條件](quiz-remainder-pair-20261117.md)。

## 原題作答要求與特殊表格關卡（2026-11-17）

- 題目由結果欄改為須保存算式／直式時，同步檢查學生提示：算式提示輸入、直式提示手寫，不保留「只填數值」或含糊的「原題要求」系統語。`quiz_work_prompt.py` 只替換已知匯入提示的完整文字及版面 run；須先證明原題要求與相符的原生保存契約，未知提示退回。另建候選 ID，保存舊內容與收據，重驗新 ID 的存答／接回／回顧，不修改既有作答。
- 比大小題優先用程式把原教師鍵、固定複核與獨立精確計算逐位置核對；數值或符號一樣不代表量綱一致，公斤／公克須先換成相同單位。完整多式才用 fields，每式緊接自己的選項；單一式不套多欄。原件、來源指紋及一對一位置保持，不猜圖內格位。[嚴格比較符號轉換與驗收](quiz-comparison-source-20261117.md)。
- 桌手機 fixture 必須使用正式頁面的容器 ID、body 類別、年級及樣式範圍；例如正式樣式以 `#server-quiz` 為範圍，用 `#root` 通過不代表正式畫面通過。內容呈現調整後重驗，不能沿用調整前的截圖。
- 回顧驗收必須先取得實際 SQL／API 產出的回應，再交給共用呈現程式；禁止在 fixture 人工補出正式回應缺少的欄位後宣稱通過。個人保存成功不代表夥伴可回顧，須分別核本人／他人、未揭答／已揭答、最新訂正／歷史保持與桌手機。隔離資料、正式回滾與正式上線收據分開；詳見[共同回顧筆跡缺口及修正關卡](quiz-peer-sketch-review-20261117.md)。
- 必須同讀 NAS 原題、教師鍵與 `catalog.item_types[].name`。書商常把「寫出算式／直式」放在題型名稱，Word 題幹未必重複；不能只依題幹或 AI 的 `auto_grade` 判定最後數值已足夠。使用 `quiz_source_work_requirements.py` 檢查，缺題型資料直接退回；有列式、直式、作圖、塗色或連線要求者，未證明全部作答可保存前不得列入結果欄候選。
- **2026-11-18 使用者確認，取代先前算式一律手寫的規則：**一般「寫出算式／列式／把做法和答案記下來」使用可打字及按數字、運算符號的輸入介面；只有 NAS 原題或原出版題型明確要求「直式」才使用可保存的手寫介面。不得由除法單元、教師例解用了直式或模型標籤，推定學生必須寫直式。作圖、塗色與連線依各自原題要求另驗，不套算式規則。
- 固定答案欄由程式判分，算式／直式過程與答案在**原本一次送出**中保存，不另加必填自評流程；只能說「答案欄答對」，不能把數值正確當成過程也通過。參考解法在原揭答條件成立後供核對，合理不同算式不得因字串不相同被判錯。當頁計算紙、本機 Map／原型伺服器不算正式保存證據。必驗一次送答、重試、接回、個人／整份回顧、夥伴完成前不洩漏及完成後核對、身分隔離。不得把筆跡塞進文字答案、隱藏 ID 或繞過原長度限制；需新 DB 函式時先備妥 SQL、測試與 PR，再取得明確核准。
- 每次修正須掃描全部同類來源與已轉化候選，分列「純結果／算式輸入／明確直式手寫／作圖等須另核」，保存來源題型、題文證據、原檔 SHA、舊新 ID 與修正收據。對已發布或已有作答的題目建立新候選版本，舊題及既有作答原樣保留；未知或混合要求不得猜測批改。
- **真正開放作答／作圖**的手寫候選採 `open`／`input:sketch` 與正式獨立驗證／容量契約，沿用既有人工核對／自評；**固定數值＋直式過程**改用上方 `fields.work` 同次保存，不因需要手寫就把整題轉成open。兩者都不把筆跡塞成文字或視為自動正確，必驗個人／夥伴、接回／完整回顧、未揭參考、筆跡／顏色、重試及舊作答保持。塗色／連線等還須核原圖底板及圖位，不能一律換成空白畫板。真正開放題細節見[手寫保存契約](quiz-open-sketch-20261117.md)；本次固定答案與過程的不同契約見[算式／直式分流](quiz-saved-work-input-20261118.md)。
- 紙本「打ˇ」改為線上操作提示時，使用 `quiz_choice_source_instructions.py` 的中性規則，只適用已核實的單選；不得把重量、面積、長度等其他題目一起替換成特定題意。單選保持 `single`，真正多小題才用 `fields`。
- 合併表格不得直接丟棄跨度資訊。`quiz_price_table_projection.py` 只接受已核對的分類／價格合併表頭或末列全寬備註，保留全部價格／原備註；其他合併型態退回。`quiz_docx_merged_table.py` 從原 Word XML 保留合併格，遇圖像、公式、未知樣式或缺格拒絕猜測。完整原件／模型與學生可讀投影分開留存；課表投影僅限明確「星期幾沒有數學」的單題，核完整七節與每週課程、唯一原鍵及桌手機可讀性，不泛用到時間或其他課表題。
- 「技術測試通過」「來源要求完整」「整科可發布」分開登記。退修後重算內容 SHA／question ID 並重跑受影響的存答與桌手機，不沿用舊畫面收據；整科未通過不分批啟用。

## 1. 接手先還原可執行狀態

1. 讀最新交接及正式收據，核對 `origin/main`、`live-proof`、原件／候選 SHA、已送出 journal、現在工作程序及待答問題。優先採較新的正式回讀，歷史 queue 的 `production_added=0` 不能覆寫後來的上線證據。
2. 列出「已正式啟用」「已通過可接發布」「待複核」「局部阻塞」「下一個可執行工作」，各記實際檔案及接續命令；不要只寫「繼續處理」。
3. 檢查 C／D／工作碟可用空間，再決定批次大小。讀取已知目錄與確切檔案，避免反覆遞迴整個大型工作根。原始對話只在有爭點時漸進讀取，不把巨型 transcript 整包送模型。
4. 新修改先 fetch，再從最新 main 建新分支／worktree；主工作區只讀。私有來源、暫存及審查證據另存，單一工作樹只有一位寫入者。

## 2. 分清三種登入，不讓網頁登入綁住整個工作

| 通道 | 要查的證據 | 不能據此推論 |
| --- | --- | --- |
| Google Drive 桌面版／檔案總管 | 程式是否執行、真實掛載、目前可見帳號、目標資料夾、讀寫／同步狀態 | 一個 Drive 網頁要求密碼，就認定桌面版也登出 |
| 既有窄授權 API | 不顯示秘密的 token 更新結果、實際帳號、目標資料夾與 owner-only 權限 | 網頁 cookie 過期就認定 OAuth 失效；token 能更新就聲稱瀏覽器已登入 |
| 瀏覽器／Notebook／書商 | 選定實例與精確 target 的可見帳號、實際登入頁／錯誤 | 用 `/u/0`、頁籤位置或其他服務的登入，猜本服務身分 |

### Google Drive 的操作順序

1. **使用者指定桌面版時，先查桌面版與檔案總管。** 從已有私有附錄找掛載與目標；不能另找連結器或先開網頁登入，把它當桌面檔案操作的必要條件。磁碟代號會變，必須核實，不硬編。
2. 已有本機素材先比 SHA、檔案數與大小；缺雲端媒體的批次才準備上傳。只用既有私有資料夾，不開 anyone-with-link。檔名叫「桌面複製 receipt」但只有本機檔案清冊，不算已複製／已同步證據。
3. 按選用通道核實實際可見帳號後才做新增／上傳。桌面版可見帳號與瀏覽器帳號是不同證據；桌面版的實際可見帳號可納入明確的 desktop 身分證據分支，不得偽造網頁帳號證據。
4. 桌面複製到既有授權路徑後，另驗同步及遠端 metadata／下載 SHA，取得正式媒體 ID，再做 Worker 註冊。複製完成不等於同步完成，更不等於已可由學生存取。窄授權若看不到桌面新增檔案，保留「待註冊」，不私自擴大 OAuth 權限。
5. 如需既有 API 註冊，先用**只讀** preflight 核既有授權、帳號與私有 parent。這不授權省略上傳所需的可見帳號檢查；若原 helper 只接受 web 證據，須新增可驗的 desktop 分支並核對帳號／目標一致，而不是刪掉 guard 或填假的 passed。
6. 不把教材儲存帳號、Notebook 帳號與書商帳號混用。Notebook 登入成功不代表可改用該帳號存教材；書商登入也不等同 Drive 登入。
7. 只有已證明目前真正需要的通道無法恢復，才一次提出最小人工登入請求，附失敗證據、精確頁面及所需動作。不得收集密碼、代過驗證碼、把未回覆視為同意，亦不反覆開新登入頁。人工登入等待期間繼續其他工作。

## 3. AI 生產、複核與失敗分流

### 原 Word 數值鍵、答案縮圖與過程保存（2026-11-17）

- 書商的`content.webp`可能同時含原題、教師答案及解析；只能先當私有校對證據，不能因檔名含content就直接上傳給學生。學生素材從已核SHA的`preamble-question.docx.gz`等無答案原件抽取；教師Word與縮圖分開留存。縮圖與教師Word不一致時，保留差異及獨立計算核對，不能用縮圖蓋掉原答案鍵。
- 已有固定複核的純數值／分數，使用`automation/lib/quiz_numeric_teacher_keys.py`核原教師鍵與每個複核位置。先辨別完整、連續的括號／圈碼／注音代號，再做NFKC，避免把①2/8變成12/8；中間缺鍵、非連續代號、未知圖位、帶分數、千分位及多段答案均退回對照，不猜補。原表可用`match_teacher_table_keys()`逐表配對：行列形狀與全部已印字／圖必須相同，只取原題空白、教師填數值的格子；保留雙方表索引及列欄。重複匹配、合併表或原表數值變更不放行；所有取值仍須與完整複核位置數／順序相等，不能拿部分格位當整題完成。測試：`python -X utf8 -B automation/tests/test_quiz_numeric_teacher_keys.py`。
- 僅在無過程要求、明確有「答：」結論且全部數值與位置逐一吻合時，才能從該結論核最終數值；不能從直式／算式過程抽幾個數字當答案。這個鍵核對器不決定題型、欄位、圖位、複數合理答案或是否已可發布；仍須核原件、全部答格順序、課本原檔SHA／PDF頁／印刷頁、公式及實際呈現與判分。
- 表內答格標記使用短圈號等清楚錨點，答案欄帶原列／欄名稱與相同錨點；不要在窄表格每格反覆塞「第幾格」，使手機文字被擠成多行。保留原表數值、對應及一次送出，內容標示調整後重新綁定候選SHA並補驗。DOM數量正確、圖片已載入及沒有頁面溢出，只是程式關卡；還須目視表格與答欄是否真的容易對照，不能將初版合成檢查通過當成可讀性已通過。
- 若原題要求直式、算式、說明或畫圖，必須先確認現行adapter真的能保存與接回。個人計算紙只有當頁記憶體，不能當成已保存的作答；固定複核文字寫「由畫布保留」也不能取代功能證據。現有數學normalizer不會解算式或自動評畫圖；未有適配不得只收最後數字、把整題改成普通文字，或宣稱已完成原作答要求。局部受阻不停止其他已授權題目的轉化。

### 多欄題揭答必須就地標示（2026-11-16）

- **跨科與舊卷不能只沿用一題通過紀錄（2026-11-17）**：每次共用核對修改後，掃描各課程啟用／停用來源、固定版本／草稿及歷史考古版本；建立「課程／題型 × 個人答題／整份回顧／夥伴答題與共同回顧 × 桌手機」矩陣，不能只驗當前科目或只看頁尾解析。`node automation/audit-review-coverage.mjs --input <私有來源> --copies <私有固定卷> --past <私有考古版本> --courses <私有課程索引> --out <私有報告> --check`須無未知參考／來源修改；程式全量盤點與畫面代表驗收數分開記錄，未實測真人房間／媒體不能冒稱已測。
- 一般單選的整份回顧也須標出原選錯項與正確答案；考古卷每欄結果須留在原控制旁，不被通用收集器搬到頁尾。夥伴考古選擇／勾選／配對／複選／排序答完後保留原控制並鎖定，隱藏欄位保留原JSON回應值；編輯／尚未揭答不顯示參考標記。共同回顧只根據後端明確提供的typed參考，不能把考古`correct:0`占位值當首個正解；布林false、數字0均不能用truthy判斷是否有答案。手寫、畫圖與自評不自動標對錯。驗收須確認畫面實際可見並目視截圖，不能只數隱藏DOM就稱可讀。詳[跨科與舊卷核對覆蓋](quiz-review-cross-course-20261117.md)。
- 不能只把已勾選項目染藍，再在底下輸出一整段「核對每格」。在每個小題及原選項旁顯示文字／符號：選對、選錯、漏選；配合綠、紅、黃虛線區分，不能只靠顏色。保留原勾選位置、選項ID、已存作答、外層dock與整組一次送出，不增加逐小題確認或提交。
- 共用`quiz-fields-review.mjs`只以**後端已允許揭答**的參考答案與已存回應做呈現比對，不讀題目私有answer、不新增前端分數或覆寫後端判分。送答中、尚未揭答、草稿／訂正編輯時不顯示核對標記；開放題仍走原自評流程。
- set按原ID集合比對、sequence保留順序，明確「都不選」與未作答分開。多個可接受選法先找完全相符版本；未完全符合時，只標一定選錯／一定漏選的項目，其他選法在原小題旁列出，不任選一版當唯一正解。跨欄tuple配對未符合時整組就地提示核對，列完整可接受配對，不把各欄獨立接受就誤稱整組正確。
- 數學／文字不能僅因字面不同判錯；非完全相符者並列原作答與參考，保留後端正確結果，不另猜數值等價。已送出後改用「核對作答」文案；有需修正欄位時帶到第一個問題處，避免只跳到頁尾總解析。
- 個人初答揭答、接回、整份回顧、錯題與夥伴原欄位／共同回顧共用；沒有自己的作答時只列逐欄參考，不杜撰他人或自己的對錯。必驗未揭答／編輯時隱藏、選錯與漏選、明確都不選、多接受答案、配對、數學文字、原封包及桌手機；來源媒體、原外層與後端判分保持。詳[修正與驗收](quiz-fields-review-feedback-20261116.md)。

### 期末短選項的紙本結尾句點（2026-11-18）

- **題幹提到句子，不等於選項是完整句子**：例如「句子中哪個字錯誤」提供「桶、網、愈、硬。」仍是單字選項，不能因題幹含「句子」整題排除。先分辨是否明確辨字／讀音／字形等任務，再檢查完整選項組；「的、得、地」等本身是作答單字時，不套一般片語的功能字排除。標點／引號／語氣任務及真正句子選項仍保留。回歸與桌手機須包含實際漏例，不能只沿用上一題通過紀錄。

- 本次使用者授權僅限期末範圍；先用 `quiz-practice-scope.mjs` 的已核對課程／單元邊界分類來源。期中、混合來源、未知範圍及考古卷不套本次規則，不能因短選項末尾有「。」就跨範圍刪除。固定卷中來自期末的原題可沿用已核定來源的呈現；明確期中副本與同 ID 衝突時保守保留。
- 程式先確認完整選項組只有**原本最後一項**帶句點，且全部是明確短詞／名稱或純數值與單位；完整句子、引文、標點／語氣／句意／敘述辨識題、圖片、無法對齊的 rich 內容及不明短語保留。小數點、單位、數值、內文標點均不刪；不整庫送 AI、不逐頁改 DOM。未知項列入掃描保留原因，不冒稱已清空所有句點。
- `audit-option-periods.mjs` 產生期末限定的題目 ID／欄位／完整內容指紋／原選項 ID 清冊，`quiz-option-periods.mjs` 在共用轉換層只投影顯示文字。原 NAS／光碟、資料庫題目及固定版本不改，選項／欄位 ID、正解、既有回應、亂序及原外層一次送出保持；亂序後按原 ID 處理，不刪畫面最後一項。題文或完整選項組改變時指紋失配即保留，須重掃後才能擴充清冊。新來源啟用前也須重跑同一掃描，不能沿用不相符的舊 ID。
- 每次核對啟用／停用來源、固定卷、草稿與夥伴副本，分列候選／保留／範圍外。使用正式 `quiz_student_document` 的亂序投影驗證，並檢查來源不變、ID／答案／回應契約不變、冪等、閱讀相容指紋及個人／整份回顧／夥伴文字與 rich 一致；桌手機沿用正式容器與共用呈現。只有函式變更才另外走 SQL 核准，本次為純呈現、不改資料庫。詳[掃描、驗收與發布紀錄](quiz-final-option-periods-20261118.md)。

### 選項原序標記不得與畫面徽章重複（2026-11-16）

- A／B／C／D由既有共用介面產生；單選選項正文不要再帶紙本①②③④、(1)(2)、1.／1、或(A)(B)等同一層原序標記。共用`quiz-option-labels.mjs`只在完整、唯一、可辨識的一組標記與非空完整內容間去掉前綴，支援原選項亂序，原ID、順序、答案與既有作答值不變；不得逐頁用正規表示式刪字或整庫重送AI。
- 先判別標記用途：純數字、金額、年份、小數、算式、變數組合、原圖位置與原文句子引用不是單純裝飾。沒有明確標記的「1 公尺」不刪1；圖位選項可去掉多餘前綴，但正文中的原圖①必須保留。文章以①②標記句子而選項在解釋那些句子時，保留引用關係；不能看到完整①～④就盲目刪除。勾選／排序等沒有重複單選徽章的原型別不套此規則。
- 修正在`convertChoiceQuestion()`共用入口的呈現／新來源轉換層進行，不能只修畫面DOM；個人答題、接回、整份回顧、錯題與夥伴純文字／rich內容都要一致。經原件核對的閱讀相容指紋只為等義呈現變更增補新指紋，保留舊指紋及原來源SHA，不放寬未知來源guard。
- 每次修正後掃描啟用／停用來源、固定卷／草稿與歷史考古版本。`node automation/audit-option-labels.mjs --input <私有來源JSON> --copies <私有固定卷JSON> --past <私有考古版本JSON> --out <私有報告> --presentation-check`檢查剩餘呈現問題；新候選以同命令`--check`阻擋可修前綴尚未消除。報告要分開列「單選修正」「非單選保留」「題意引用保留」，不能用所有圈碼命中數當錯題數。
- 驗收包含圈碼／數字／字母、全形標記、原選項亂序、純數值及句子引用反例、rich段落／原圖片、single與fields、原送答封包、已存作答與夥伴草稿；原外層及整組一次送出不改。前一項閱讀圖位／字詞庫／表格的原件核對、媒體SHA與逐欄對照仍為必要關卡，不能以本次消標記代替。見[本次修正紀錄](quiz-option-prefix-repair-20261116.md)。

### 閱讀題組呈現與小題對照（2026-11-16）

- **原件核對後才能解除待查**：先列NAS光碟目錄，只提取所需原件／MDB／書籤，不複製整張ISO到C碟。圖位須對照原頁與原圖順序；共用字詞庫須驗每個原代號與完整詞句；特殊表格須核父子題、列／欄及作答欄的對應。NAS缺少對應版本時，改核已保存原件的完整SHA與正式來源溯源，明記其來源，不拿別版本同名題替代。詳見[53筆來源核對](quiz-reading-nas-review-20261116.md)。
- 經核對的特殊來源只登記題目ID、內容／欄位相容指紋、結構映射與來源SHA；不把原Word教師答案、原題全文或私有媒體提交公開repo。相容指紋不含答案，也不是認證／判分機制；題文、媒體、欄位或選項改變時，掃描須退回待核對，不因同ID或一般規則能顯示而沿用舊通過紀錄。
- 呈現投影可將完整字詞取代裸A/B/C代號、將圖片移到對應欄內及將空格編號，保留原欄位型別、欄位／選項ID與順序。長表格保留完整共用參照，欄位須能定位原列／欄；不得把圖表裁成猜測的小題。只刪已辨識的機械匯入前綴，保留實質教學修訂、條件及原資料時間。
- 原圖驗收須核實際圖片位元組SHA與載入，不以佔位圖代替。個人桌手機須驗整組送答原封包、已存作答接回與完整回顧；夥伴另驗共用欄位樣式、草稿原值及圖片位置。把圖片放在fieldset內文，避免高圖片塞入legend造成框線穿圖。局部調整後補驗受影響案例，完整驗收與補驗數字分開記錄。
- 每次修改共用閱讀規則後，必須掃描**未命中規則的題目**，涵蓋其他科目、啟用／停用來源、固定卷與歷史版本；不能以「保留原樣」當驗收通過。用`automation/audit-reading-groups.mjs`保留逐項分類與待查理由，新候選以`--check`阻擋未定案對應。來源若是純填寫／字詞庫／圖位／表格／多層題，分開記錄；不得為湊通過率猜配。
- 支援全形數字、空白後題號、不同欄位標籤，以及前填空後閱讀選擇；逐欄保留原型別、ID與整組提交。英語A/B/C等代號需有完整原來源銀行才能改顯示完整選項；最後單字注釋、原圖及表格不可漏。圖位或父子題只有原件能定義時，留來源對照並列待查，不擅自裁切或重排圖位。詳見[跨科目與歷史盤點](quiz-reading-cross-subject-audit-20261116.md)。

- 程式優先區分共用文章與小題；小題題文必須緊接自己的選項，禁止只在答題欄留(1)／(2)卻把全部小題集中在文章末尾。連續編號、數量與欄位須完全對應；不能可靠分割者保留原文並列人工檢查，不交AI重寫整庫。

### 解析不得用原選項位置定位（2026-11-16 使用者糾正）

- 單選選項會依作答場次亂序；原題①、原第1個選項或原A，不能直接當成學生畫面目前的A／B／C／D。正確答案必須以固定選項ID判分，解析優先寫完整選項內容，例如「『世界貿易組織簡稱WHO』這項敘述錯誤」，禁止只寫「因此①敘述錯誤」。不能為了配合解析停用原有亂序。
- 新來源凍結前，由共用 `canonicalizeQuestion()` 依來源原始選項順序／ID轉成內容引用；AI解析與書商解析都要檢查，課本頁碼仍依原證據對照。學習包的 `student_explanation` 另同步檢核，不因來源題目已轉換就漏掉學習解析。執行 `node automation/audit-explanation-references.mjs --check --input <私有候選絕對路徑>`；單選或單一選擇欄位仍有可替換的位置引用／無可靠映射時非零退出，修正候選後再過關，不將整庫重送AI。
- 舊固定卷與歷史作答不覆寫。學生呈現以 `quiz-explanation-references.mjs` 讀取經來源核對、僅含題目ID／選項ID的原序映射，依當下選項ID找內容；圖示沒有可讀文字時才顯示當下真實選項字母。不得依畫面第幾格猜回原序，不得把答案ID當畫面字母。
- 機械掃描不能把日期、數量、步驟、表格圖例或小題號當成選項代號。現行多欄內選項未亂序，圈碼也可能是小題標號，須保留原完整題組，不套單一選項的位置替換；若未來改成多欄亂序，須另建逐欄原序映射與驗收，不能沿用此例外。無來源、原序衝突或對應不明者列疑義，不猜改。
- 必驗同題至少三種顯示排列、所有選項輪替位置、是非／圖示／單選欄位、初答／訂正／接回／整份回顧及夥伴呈現；原答案、送答ID、亂序、儲存與原外層介面不變。檢查解析實際文字，不能只看正確答案徽章對了就算通過。
- 題幹前獨立的「是非題」「選擇題」僅在學生呈現隱去；原來源與題型分類保留。不得刪實際題意裡的相關詞，也不能讓舊圈碼選擇欄位因標題被隱去而退回文字輸入。

### 題型先依作答契約決定，禁止一律包成 fields（2026-11-16）

1. 單一選擇、單一是非判斷使用外層 `single`，選項帶完整內容、答案對應選項 ID。不得因同一批有多欄題，就把整批單選包成一個 `fields`。真正多欄整組才保留多欄契約；現行 schema 中的勾選集合 `set`、排序 `sequence` 及特殊欄位，仍使用原本結構化控制，不冒充單選、不改成逐項是非。單欄但接受多個合理選項者須保留原接受答案集合。
2. 共用來源轉換入口為 `shared/quiz-question-contract.mjs` 的 `canonicalizeQuestion()`。輸入為來源副本；輸出新題與明確欄位／選項映射，不改原件。舊注音／國語圈碼選項若不符合外層 single 的 ASCII ID 契約，只在新版本映射為 `c1…`，保留雙向映射、原碼與完整選項內容；不能直接搬圈碼使正式 validator 拒絕。
3. 每個來源轉換器在凍結候選版本前，必須跑 `node automation/canonicalize-quiz-questions.mjs --input <私有絕對路徑> --output <另一私有絕對路徑> --report <私有報告絕對路徑>`。再對輸出跑 `--check --input <私有候選絕對路徑>`，要求 `type_changes:0`、`issues:0`；不能只改一支匯入器而讓其他科目的私有腳本繼續一律產生 fields。既有停用瑕疵來源另冊隔離，不能重啟用。
4. 既有正式來源採新不可變版本修正：`automation/plan-canonical-quiz-repair.mjs` 只產生私有候選與 guarded SQL；新題沿用課本、頁碼、學習重點、媒體及來源證據，舊來源停止供新組卷抽取。固定卷、既有草稿／作答、訂正與獎勵不得改寫。先 rollback 演練所有選項的新舊實際判分一致，再啟用新版本。API 大小限制可分批，但每批須先全數通過驗收、檢核原列未變，保護資料摘要保持；不得因上傳太大略過 guard。
5. 夥伴支援須驗完整鏈：共用 catalog → 所有符合 10／20 題容量與所有權條件的自組卷／教師卷 → 私有房間副本 → 原控制型別 → 原固定送出 → 原判分或開放題不自動判分 → 揭答／共同回顧 → 草稿、重送、訂正及獎勵。不能只放寬按鈕 gate。多欄整組維持同一位學生、一次送出；題目媒體與解析媒體繼續遵守成員與揭答限制。
6. 夥伴入口與個人練習使用不同顏色，沿用共用 `quiz-partner-pilot-entry.mjs`；必驗期中、期末、新組卷不重新整理皆能補按鈕。個人原外層 workspace、儲存／作答流程不因內容或型別修正而另造一套。

6. **驗收與發布**：自動題以原判分函式驗正答／改答／非法值一致；開放題維持例答非唯一解、自評不混入自動對錯。桌手機逐筆驗實際共用元件、教師預覽、原外層單次送出／接回／自評；無真人OAuth時如實記隔離合成身分。原件與正式資料不需改寫的內容缺陷，用純呈現相容修正並依main發布；原選項真的缺漏則走前節的新版本修復，不改不可變舊卷。Windows舊SQL fixture需用Git原始LF內容核指紋，不放寬guard或改正式SQL讓測試過。

### 來源留存與學生呈現分開：勾選題內容關卡（2026-11-16）

- **來源層**：不可變原件、完整原題、原題型、原鍵、校訂理由／證據與SHA保留於私有來源及審查紀錄。完整留存不等於整份全文都放進學生題幹；共用呈現函式從原資料建立學生畫面，不把校訂紀錄、原鍵或重複全文顯示成題目。本輪為前端相容呈現，固定資料及原RPC契約仍保留，不能冒稱已重寫後端題目payload。
- **學生呈現層**：共同情境只顯示一次，敘述直接作為勾選選項，不在題幹重複列出。保留 `set`／checkbox、欄位ID、選項ID／順序、答案鍵、`fields-v1`回應與原有一次送出；不另加逐項正誤按鈕、完成計數、確認摘要或內層送出。全不選與尚未作答仍須區分，既有「這些選項都不選」維持明確互斥且初始不預選。**使用者已確認內容精簡，但明確要求不改原外層作答介面**：不把獨立示範的外框、卡片、字級或操作流程套回正式站；原 `quiz-server`／`quiz-fields`／workspace／CSS 不因內容清理而改動。
- **共用程式**：`convertChoiceQuestion()` 接到 `quiz-checkbox-presentation.mjs`；`quiz-content-slices.mjs`保留原段落、run樣式及媒體對應。依完整可選文字對應有編號的來源行，或完整圈號選項列；多小題以原欄位標籤綁定小題區段，不能只憑相同選項或數量猜拆。只有原選項編號與純圖位置明確相符時，原圖才移到對應選項並保留既有文字說明。不移除閱讀段落中自然提到的相同詞語、共用詞庫、必要條件、圖表或「選出錯誤項」等題意。刪除敘述後也清除空段落／多餘換行，不留下大片空白。未知校訂或缺原選項須列待核。
- **內容校訂須另核**：不能只把「第幾項改為……」堆在學生題目前，卻保留舊選項。必須明確綁定題目ID、欄位／選項ID、待替換原句、已核修訂句及被移出的完整校訂註記；條件不符即停止該題。核過的必要假設可精簡留於情境。實質內容／答案修訂仍依不可變新版本流程，呈現函式不自行推答案、不把一般題庫方式套到需保留原貌的考古卷。
- **資料驗收**：執行 `node automation/audit-checkbox-content.mjs --input <正式只讀匯出.private.json> --report <報告.private.json> --output <不同路徑候選.private.json>`，掃題庫來源及固定卷／草稿／夥伴副本，分開計來源、欄位、副本與可用狀態。`checkboxPresentationIssues()` 檢查有作答標記的題幹／選項重複、匯入說明殘留、原題型／欄位／選項ID／答案契約；另核來源SHA、輸入未改、媒體不缺、轉換冪等與原題選項覆蓋數。未解校訂或缺項不能因函式回傳原題就算通過。機械轉換不逐題送AI。
- **實際畫面驗收**：桌機與手機逐項查「情境一次、各敘述一次、選項文字清楚、只有原有一次送出」。實點多選、取消、全不選互斥、初始空白、原ID回應、保存／重載及課本關閉後返回同題；確認沒有新增正誤流程或二次確認。欄位齊全、可送答、無橫向溢出不能代替上述檢查。正式批次還須依實際個人／夥伴／回顧／教師入口與判分驗收，獨立頁不冒稱已驗正式授權或寫入。
- **缺項獨立修復**：原題四項卻只存三個選項時，不能只去重掩蓋缺項，也不能向舊不可變版本直接添加ID。核完整來源及原鍵後，建立保留全部選項的新版本，交易回滾驗正確／錯誤／新選項及學習對照，再指紋守衛啟用；舊來源退出未來組卷，既有固定卷／作答不改。機械補回漏掉的錯誤選項不代表原審查收據可冒稱已驗過新候選。
- **本輪範圍**：示範內容已獲確認，依使用者授權掃描並批次修內容，外框保持；不重匯全庫、不整庫重送AI、不變更資料庫函式／權限。發布仍依PR進main及正式發布腳本。

每次完成／失敗／人工問題後，都更新下一個可執行工作：

| 情況 | 保留／阻擋範圍 | 仍應執行 |
| --- | --- | --- |
| Drive 網頁停密碼頁 | 該 web 通道；未證明其他通道失效 | 查既有桌面掛載／可見帳號與只讀 API preflight；無新媒體批次及其他科目繼續 |

## 5. 圖文與教材的固定品質規則

### 課本參考頁碼對照：獨立必經階段（2026-11-16）

已發卷的頁碼勘誤須同時核對標示、點擊開頁與本題頁返回；不得只換顯示文字。不可變來源與既有作答保持，固定勘誤層只匹配核定題目／教材／原對照，並使用已授權、SHA相符的頁面；缺正確頁不能繼續顯示已知錯頁。後續新來源依勘誤證據重新固定對照。三年級國語一筆95～96→94頁實例見[收據](quiz-g3ch-page94-20261118.md)。

完整流程為「來源／版本核對 → 題目程式轉換與初檢 → 解析／學習重點整理 → 指定教材頁碼候選與內容核對 → 固定逐題對照 → 全量資料／媒體與實際入口驗收 → 整科發布」。即使題目已能作答、判分或已有書商解析，仍須完成教材對照與驗收。

1. **先固定正確教材與頁碼索引**：核學年度、年級、書商、冊次／學期、教材種類及原件指紋；分清印刷頁、PDF檔案頁序、電子書資產位置。以印刷頁供學生辨認，保存其到實際資產的對應。來源可為原PDF或原電子書SVG／字型，未取得PDF不得冒稱已取得。依下列各校教材規則選課本／教冊，不拿習作補配。
2. **程式先找候選，重用已核對照**：利用題目單元、可靠知識點、課本文字／圖表索引及關鍵詞縮小候選。已核對的同版本、同一具體學習重點可重用頁碼，並檢查新題是否超出該重點；同單元或出現相同關鍵詞只能當候選，不自動當確定對照。此為執行流程要求，不表示目前已有通用全自動配頁引擎。
3. **核原頁是否支持題目與解析**：開候選整頁核正文、圖表、條件與相鄰頁，依需要由Codex／已授權AI處理理解性判讀。多題同一重點集中核教材證據，避免逐題重送整本書；新條件、跨重點題或疑義仍各自核實。一題可對多頁；應用題可列相關觀念頁，但必須明示「相關觀念」，不能冒稱該頁直接包含題目答案或所有延伸資訊。
4. **固定逐題對照與缺項原因**：依現有schema／adapter保存題目／版本、教材版本與來源指紋、印刷頁及資產對應、對照類型、理由與複核紀錄。分開記「直接支持」「相關觀念」「查核後無可靠對照」「尚待核對」；未處理不等於無可靠對照。查無可靠頁碼保留固定解析並如實標記，不硬配，也不因此停掉其他已核工作。
5. **程式與畫面都驗**：檢查每題是否已有狀態、版本／頁碼／資產是否存在且一致、私有媒體能否以正確角色取得，學生實際開啟是否為標示的印刷頁；驗桌手機翻頁、關閉及返回原題同次作答。題目、解析、教材版本或對照內容改動時，只重核受影響的對照並重新固定版本，不沿用舊收據或改寫歷史作答。
6. **整科交付列覆蓋數及限制**：分開回報有對照來源數、直接支持／相關觀念／無可靠對照／待核數量；同題多頁及重用同一教材頁不重複算題。必要題目仍待核時不得宣稱整科對照完成；查核後確實缺可靠教材則明示限制。學生日常開頁讀固定對照與已授權素材，不即時呼叫AI配頁。

- 以指定教材的印刷頁碼為主，與 PDF 頁序分開；整頁參照，一題可多頁、應用題可標相關觀念頁，保留拉頁。既有解析也重新核對。頂溪三／六與土城四以課本為主；不足查教冊，學生端只作文字補充並註源；不參考習作。
- 學習重點給老師，學生解析用短句與適齡語言；數值算對也要核圖、格數、選項、公式與教材支持範圍。兩個 AI 一致不是證明。
- 一般題庫可依證據最小改寫，完整保留原件與修訂紀錄；考古卷保留原貌並加勘誤，爭議題不硬開自動計分。作答欄位與真實作答目標對齊，不以空格數或圖片占位猜答案。
- 分數依 [分數與公式 QC](past-exam-playbook.md#分數與公式一般題庫考古卷共同必查) 處理：題幹／選項／表格／解析都查。WMF 可見值與 OLE 快取不同、原件 SHA 與媒體 SHA 不同；大分母、帶分數、未知／裁切公式都要處理，塗色等真正題意圖保留。

### 中正九年級教材頁碼發布關卡

課本入口放在題目與作答區下方，閱讀器須持續顯示「本題頁面」及各參考頁的返回按鈕，頁碼選單亦標示本題參考頁。多頁或跨章參考均保留，翻閱其他頁後可以直接回到本題相關頁；桌機與手機須驗位置、可見標示、跨章返回及保留選答。

1. 中正九年級自然考古卷沿用國小方式，學生端顯示自寫解析與**學生課本**對照。其他中正九年級科目依既定要求對照教師手冊。教材種類、書商、冊次、學年度、版本及原件指紋須固定。考古題依當次範圍標示歷年參考。
2. 每題須核原頁，固定教材名稱、章節、印刷頁碼及「直接支持」或「相關觀念」。查無可靠對照時逐題留下已查範圍與原因。套用學生課本對照時須核對課本本身的頁碼與內容。
3. 提供出版社可供學生使用的原址，或使用有記錄使用依據的頁面資產。整頁使用依據未確認時，可先顯示已核對的教材名稱、章節、印刷頁碼及自寫解析。含解答的教材頁須在送答後才可開啟。
   - 學生課本入口置於題目旁，答題前即可在作答頁內直接開啟指定印刷頁，作答後仍可使用；解析於送答後顯示。若出版社原檔以附件提供且允許頁面跨來源讀取，從出版社原址在瀏覽器呈現指定頁。上線前以桌機與手機實際看見指定原頁、關閉後回到同題並保留已選答案。整章下載僅作為原頁載入失敗時的備用選項。
   - 課本閱讀器提供同章完整連續頁碼及上一頁／下一頁，不能只列本題引用頁。只有一個引用頁的題目也必須可往前後閱讀；章首／章尾正確停用越界按鈕。用正式頁相同樣式檢查入口按鈕的文字與背景對比，不能只驗 DOM 有文字。正式發布後，以已登入的實際考古卷重驗按鈕可讀、連續翻頁、指定頁跳轉與返回原選答；只回讀部署檔案不足以取代此操作驗收。
4. 發布前須全量核對逐題狀態與正確版本，在桌機及手機的實際入口驗證頁碼與解析。有開頁功能時，須驗證學生身分的開頁、翻頁及返回同次作答。將覆蓋數、畫面及可開頁範圍寫入[考古題發布收據](past-exam-job-template.md#驗證與發布收據)或該批驗收紀錄。題目仍待核、頁碼未驗證或缺少查無可靠對照的證據時，該批不得上線。

### 是非題選項不可重複標示（2026-11-16 再次回報，必驗）

適用所有年級、書商的一般題庫與考古卷，包含 `fields` 題內 `input: 'single'`，不能只檢查傳統是非題。2026-11-07 已有防重複規則，11-16 六上社會仍出現「A O ○ 正確／B X × 不正確」；這是未落實驗收的回歸，不能因資料格式合法或舊套件通過而放行。

- **顯示契約**：確定是一正一反的純文字是非選項時，中文只顯示「○ 正確／× 不正確」；依既有英文規則顯示「T 正確／F 不正確」。不得再疊加 A／B 徽章、O／X 原值、第二組圓圈／叉號或相同文字。一般單選題 A／B 徽章保持；不能只憑兩選項或題幹含「判斷」就認定是非題。
- **資料與呈現分開**：來源有 O／X、○／×，甚至已帶「○ 正確／× 不正確」時，先核對來源與實際欄位，再沿共用是非呈現規則消重。若現行 helper／renderer 未支援，補齊相容呈現及驗證後才放行，不以改選項 ID、答案鍵、固定版本、草稿或既有作答來修畫面；未知／圖文混合選項人工核對，不用全域替換刪符號。
- **每批必查**：逐批列出是非表示法及其 `question.type`／`field.input`，檢查題目層與所有巢狀欄位；舊盤點工具若只掃外層 choices，不得當作 `fields` 已全驗。小樣必含本次「A O ○／B X ×」反例與 `fields/single` 真實轉化題。
- **發布驗收**：依 [是非題防回歸](past-exam-playbook.md#91-是非題轉錄與呈現防回歸2026-11-07)，實看桌機、手機的個人作答、夥伴作答、共同回顧、教師預覽與已作答摘要。另驗未選／已選／重載／揭答狀態，原 ID 的暫存、送答及判分不變，一般 A／B、圖片、複選不被誤改。保留題號、來源版本、畫面及結果；只有 JSON／SQL／舊測試通過不算呈現通過，漏驗或重複標示即退修，不宣稱整科驗收完成。

### 選擇題必須轉成完整可選內容（2026-11-16 再次回報，必驗）

六上社會實際反例：題幹末尾保留「①美國 ②英國 ③法國 ④德國」，按鈕卻只有「A ①／B ②／C ③／D ④」。此為選項未完成結構化，不能算轉化完成或只列為美觀問題。

- **學生可直接理解每個按鈕**：本例應顯示「A 美國／B 英國／C 法國／D 德國」，題幹保留問句，不重複列出相同選項。原符號若是題意本身、對應圖例或配對碼則保留，不能以全域刪除圈號處理。
- **逐項來源映射**：從原件核對每個選項的完整文字、必要圖片／公式、順序、原始 ID 與答案對應。判斷某個圈號是選項代號或真正答案內容，不能只靠圈號數量猜拆；跨段、圖文或無可靠邊界者先複核。按鈕顯示完整內容，底層仍提交原始 ID；不改正解、歷史答案或不可變版本。
- **去除轉化殘留**：單一選擇題不顯示「依原題完成全部答案欄，再一起送出」等不符合實際操作的通用文字；多欄題需要的提交提示仍保留。題幹與按鈕的同一組選項只呈現一次，不讓學生在兩處及兩套代號間來回對照。
- **必驗反例與範圍**：一般選擇題及 `fields/single` 都檢查是否只剩代號按鈕、題幹／選項是否重複、完整圖文是否保留。小樣加入本例，逐項點選後核對原始 ID、保存、重載與正錯判分；桌手機、個人／夥伴／回顧／教師預覽及摘要依實際支援入口逐一驗。資料能送出或題數正確不代表選項已轉好，缺內容即退修。

## 6. 發布是完整的一段，不只把分析檔寫出來

### 教師鍵是圖像時，先做完整像素核對

- 以`automation/lib/quiz_graphic_teacher_keys.py`核對原教師答案圖與完整選項；只接受唯一選項的原尺寸RGBA像素完全相同。不得縮放、裁切、相似度猜配，或拿整頁含答案縮圖當學生題圖。
- 教師鍵含其他文字、多圖、同一圖重複出現，或選項還有實質文字時，不能只比其中一張圖。缺唯一匹配就保留待核；不能因模型舊複核標為可自動判分就直接啟用。
- 完整來源拆分、圖像出現次數、原鍵與固定複核、課本原檔SHA／PDF頁／印刷頁仍需核對。像素相同只證明圖形鍵的對應，不代表整題驗收完成。
- 單純選擇題維持`single`及穩定選項ID。解析須用圖形特徵或選項內容，移除「選第一個／第二個／ㄅ／①」等會被亂序破壞的答案引用；原圖形序列中的第幾個仍可保留，但必須清楚指向題幹序列。
- 原Word拆分後，純單選若留下獨立且沒有圖像的「答：」或重複答句，應從學生題面移除，原件仍完整留存；有圖／表或真正需填寫的題組不能套用此清理。須目視題面，不能只靠格數與HTTP通過；改內容後換候選SHA並重跑受影響的正式存答與桌手機，不能沿用舊內容的收據。
- 數值鍵的ㄅ／ㄆ等原標號可接冒號，但必須連續且實際出現在原題文字；不得把圖內未知標號當成已對位。原格數、圖位、單位、多解及過程保存仍逐項驗收。
- 私有媒體先核現有Worker雜湊、MIME及大小，僅補缺檔；上傳後下載SHA核對，再以現行正式簽署模組驗HTTP內容。不能把本機圖片能載入當作正式媒體可用。大量Drive檔案清單要處理分頁，提交結果不明時按預配ID與journal核實，不重複建檔。

1. 內容／原鍵／印刷頁／出處及修訂固定，現行 validator 通過；學生資料與未揭答保護保持。
2. 真資料庫交易回滾、正錯判分／非法輸入／初始隱私／跨人跨級匿名教材授權，以及正式共用元件桌機手機驗證通過。
3. disabled 匯入→逐筆等值讀回→fingerprint 守衛啟用→啟用後回滾及正式回讀。改候選後換驗收版本，不沿用不同 SHA 的 receipt。未知提交結果先核 journal／readback，不能盲重試。
   - Windows重寫含SQL文字常數的驗收腳本須明定UTF-8與LF；不可讓文字換行被自動改成CRLF，再以放寬比對掩蓋差異。提交後以原候選JSON核原值、解析及版號；測試產生器本身也要assert必要守衛已寫入，不能只看「SQL執行成功」。
4. 固定 study source／版本不能直接改內容或關 trigger。修復要用既有新版本機制，保留原作答、題序、選項ID／順序、判分、計時、進度與獎勵。
5. Supabase CLI 若共用同一臨時登入角色，資料庫操作串行，避免角色競爭；不要讓多個 import／test worker 同時使用它。瀏覽器亦依選定實例及段鎖序列化。
6. 更新老師備課檢視、可公開的收據與私有接續狀態。一般題庫、考古卷、來源題數、作答位置、已分析與實際上線分開計數。驗證通過且已授權就發布，不再重問每個小段；前端發布仍遵守只從 main 的正式腳本。

## 7. 瀏覽器、視窗、磁碟與免費用量

- 背景畫面驗收不要依賴`waitForFunction`預設的`raf`輪詢；以明確間隔（通常5000ms）核實圖片自然尺寸、可見性、印刷頁及返回原作答狀態。逾時先留DOM／圖片／狀態，不以重載或改網站猜修；實例與官方依據見[背景載圖等待](browser-background-polling-20261117.md)。
- 保留使用者指定的 Notebook 本體登入，不默換分身重新請登入。使用 shared launcher 租約／心跳、worker註冊、精確target及 finally釋放；其他測試使用可分配實例。不要掃全部 profiles 或接管使用者 Chrome。
- 使用者已要求背景執行時，走 supervisor 真正的 background 分支；run 記錄須誠實標 viewer=false／background=true，保留 canary、OAuth、tool boundary、Git、marker與SHA。完成才關確切自有頁籤／viewer，不刪雲端Notebook來源、不關其他人的視窗。等待人工輸入時不可讓背景工作搶前景。
- 大檔／TEMP用已核定工作碟。每科完成後清可重建暫存，保留原件／審查／正式收據；刪除前核絕對路徑與所有權，既有自動審查拒絕不可重試繞過。
- 實查當期 Cloudflare 方案、帳戶全體與目標 Worker 用量／錯誤，記時間與證據；網頁值無法確認就報未知。不能用資產數推請求數，也不能把Google模型呼叫、本機QA或DB metadata grant算成Worker下載。接近已核免費上限時停新增會耗用該資源的操作，其他離線工作繼續；不啟用付費／overages。

## 8. 跨對話交接必須由接手者驗收

- 交接須含：最新正式數量及版本／PR、不可重跑的批次、帳號角色與通道、確切私有檔案／工具、目前鎖與worker、可續跑命令、待答問題與依賴範圍、下一個可執行工作、容量／用量證據時間。
- 將本SOP作為必讀入口，私有附錄放帳號與路徑，不把公共SOP寫成只適用單次檔名的操作稿。舊版本資訊只當歷史，不覆寫新對話後來已完成的工作。
- 由接手對話實際回報：讀到哪版SOP、如何分清三種登入、當前正式基準、哪些批次保留及現在立即執行哪一步。只說「已收到」「已讀完」不算操作驗收。
- 對話封存失敗不阻止依可靠檔案接續，也不冒稱完整封存成功；有爭點才回看原生對話。送出交接後停止兩邊同時操作同一工作線。


## 各出版題型的作答要求不得遺失（2026-11-18）

- 轉化前先核 NAS 原件、出版題型目錄及原解答，建立「題型→學生要做什麼→各欄填什麼→答案／原欄位ID」對照；不能只驗 JSON 合法，也不能等使用者發現一題才修一題。掃描須涵蓋已轉化各科、未啟用／歷史版本、固定卷／草稿、舊考古卷與夥伴副本，分開記錄掃描、修正、實際畫面驗收數量。
- 「畫掉多餘的字」保留原句中的多餘字，學生畫面明說「找出題文中多餘的字，填在下方」，欄名為「多餘的字」；輸入被刪掉的字。這和改錯字填「改正後的字」不同，不能先替學生刪字、修句或猜答案。
- 造詞、先國字／注音再造詞、國字注音、填字／詞、標點、相反詞、同部首、看圖填字、照樣寫、造句與接寫，都須檢查獨立呈現後的要求是否完整。詞語接龍須交代前詞末字接下詞首字；相同出版大類包含不同任務時，須依原件細分，不套一段通用指示。
- 只有已核原件的來源清冊與內容指紋可補說明／泛用欄名；有意義的原欄名保留。完整選項的選擇題、是非敘述、已有空格的填選題、原圖／音訊題，不因文字缺少問號或指令關鍵字就猜改。未分類項目須列待核並阻擋發布，不能默認通過。
- 共用純呈現函式處理，來源全文與答案留存分開；只補必要指示及欄名，不改原答案、欄位ID、型別、選項ID、既有作答、一次送出或外層介面。讀題組先由未改來源解析圖位／表格／小題，再加顯示說明；不因插入指令移動原解析位置。
- 個人／整份回顧／夥伴都驗相同指示與欄名；圖片媒體命名空間不同時，以相同來源資產 hash 做呈現相容比對，但不改實際 URL、授權或媒體存取檢查。內容或 hash 不符必須不套用。
- 能程式判定的批次修正與檢查，不整庫重送 AI。每型須驗原題→填答→原封裝一次提交→接回／回顧，含桌手機、圖片及開放題；不能用單題截圖或僅 SQL 正確取代。公開 repo 僅留不含原題／解答的清冊、規則與統計，私有原件及來源核對證據留 repo 外。

工具：`automation/audit-task-instructions.mjs <私有輸入> <私有報告> [清冊輸出]`。輸入含 `pool/native/copies`；`native` 必含來源ID、出版類型、DOCX SHA與必要原解答。問題／未分類非零退出；先人工核原件排除語意歧義，絕不關閉關卡。詳[本次驗收](quiz-task-instructions-20261118.md)。


## 框詞等題意標記及句子選項對位（2026-11-18）

- 「□中的詞語」的框不是空格，必須核 NAS 原 DOCX 的 `w:rPr/w:bdr` 等來源標記。不能只抽純文字，也不能依正解倒推要框哪個詞。相鄰字因不同字型拆成數個 run 時，須合併為同一框詞；字詞在手機不得拆成兩個框。
- 逐類指示檢查之外，另做「被題目引用的視覺標記是否仍在」檢查：框線、底線、箭頭、顏色／字形等有題意用途的標記不可省略。`automation/audit-docx-boxes.py` 僅核出版題目欄的直接 run 邊框，不掃教師答案／解析欄；原樣式繼承、形狀或其他標記不在此工具能力內，須另核，不能以直接邊框 0 筆宣稱整題無標記。
- 多句各選意思時，每個原句與自己的選項放在同一小題容器；不要把所有句子集中上方，只留下「第1格」在遠處。原共享詞義庫保留完整選項，不猜刪干擾項；小題、欄位、選項及答案 ID 不變，全部仍一次送出，不拆正式題目、不新增作答步驟。
- 使用來源核定的呈現指紋及框詞範圍；來源留存不改，個人、整份回顧及夥伴都走相同 `quiz-source-boxes` 與 `quiz-source-box-render`。未知版本／重複字詞定位不明／小題映射不全須阻擋，不依關鍵字一律標框。
- 小題句子不能沿用過小的欄名／legend字級：與一般題文同級，框內詞語繼承句子的字級；個人、整份回顧與夥伴的題文同步。桌機、平板及手機驗收需實際看到框線、完整詞語、每句旁的完整選項、同次保存、原值接回及各小題對錯；不能只驗有指示或有4欄。覆核已轉化原件及副本，程式能處理的不用 AI；統計清楚區分原件掃描、修改及畫面驗收。

工具：`audit-docx-boxes.py <私有來源清冊> <私有輸出>` → 核對 source boxes 與題文 → `audit-source-boxes.mjs <私有輸入> <私有報告> [來源清冊輸出]`。私有輸入的 native 含經 SHA 驗證的原件框詞與出版類型，pool/copies含來源版本；公開清冊只留範圍、指紋、來源 SHA，不放原題與答案。[本次驗收](quiz-boxed-word-layout-20261118.md)。
