# 題庫轉化長線執行 SOP

本文件規範接續、帳號、資料取得、複核、發布及局部阻塞時的執行方式；搭配 `past-exam-playbook.md` 的製作／品質規範，不取代目前 schema、登入守衛或發布規則。個別任務的最新使用者指示優先。帳號、目標資料夾 ID、實際掛載及批次狀態放私有交接附錄，不提交公開 repo。

## 1. 接手先還原可執行狀態

1. 讀最新交接及正式收據，核對 `origin/main`、`live-proof`、原件／候選 SHA、已送出 journal、現在工作程序及待答問題。優先採較新的正式回讀，歷史 queue 的 `production_added=0` 不能覆寫後來的上線證據。
2. 列出「已正式啟用」「已通過可接發布」「待複核」「局部阻塞」「下一個可執行工作」，各記實際檔案及接續命令；不要只寫「繼續處理」。
3. 檢查 C／D／工作碟可用空間，再決定批次大小。讀取已知目錄與確切檔案，避免反覆遞迴整個大型工作根。原始對話只在有爭點時漸進讀取，不把巨型 transcript 整包送模型。
4. 新修改先 fetch，再從最新 main 建新分支／worktree；主工作區只讀。私有來源、暫存及審查證據另存，單一工作樹只有一位寫入者。

## 2. 分清三種登入，不讓網頁登入綁住整個工作

| 通道 | 要查的證據 | 不能據此推論 |
| --- | --- | --- |
| Google Drive 桌面版／檔案總管 | 程式是否執行、真實掛載、目前可見帳號、目標資料夾、讀寫／同步狀態 | 一個 Drive 網頁要求密碼，就認定桌面版也登出 |
| 既有窄授權 API | 不顯示秘密的 token 更新結果、實際帳號、目標資料夾與 owner-only 權限 | 網頁 cookie 過期就認定 OAuth 失效；token 能更新就聲稱瀏覽器已登入 |
| 瀏覽器／Notebook／書商 | 選定實例與精確 target 的可見帳號、實際登入頁／錯誤 | 用 `/u/0`、頁籤位置或其他服務的登入，猜本服務身分 |

### Google Drive 的操作順序

1. **使用者指定桌面版時，先查桌面版與檔案總管。** 從已有私有附錄找掛載與目標；不能另找連結器或先開網頁登入，把它當桌面檔案操作的必要條件。磁碟代號會變，必須核實，不硬編。
2. 已有本機素材先比 SHA、檔案數與大小；缺雲端媒體的批次才準備上傳。只用既有私有資料夾，不開 anyone-with-link。檔名叫「桌面複製 receipt」但只有本機檔案清冊，不算已複製／已同步證據。
3. 按選用通道核實實際可見帳號後才做新增／上傳。桌面版可見帳號與瀏覽器帳號是不同證據；桌面版的實際可見帳號可納入明確的 desktop 身分證據分支，不得偽造網頁帳號證據。
4. 桌面複製到既有授權路徑後，另驗同步及遠端 metadata／下載 SHA，取得正式媒體 ID，再做 Worker 註冊。複製完成不等於同步完成，更不等於已可由學生存取。窄授權若看不到桌面新增檔案，保留「待註冊」，不私自擴大 OAuth 權限。
5. 如需既有 API 註冊，先用**只讀** preflight 核既有授權、帳號與私有 parent。這不授權省略上傳所需的可見帳號檢查；若原 helper 只接受 web 證據，須新增可驗的 desktop 分支並核對帳號／目標一致，而不是刪掉 guard 或填假的 passed。
6. 不把教材儲存帳號、Notebook 帳號與書商帳號混用。Notebook 登入成功不代表可改用該帳號存教材；書商登入也不等同 Drive 登入。
7. 只有已證明目前真正需要的通道無法恢復，才一次提出最小人工登入請求，附失敗證據、精確頁面及所需動作。不得收集密碼、代過驗證碼、把未回覆視為同意，亦不反覆開新登入頁。人工登入等待期間繼續其他工作。

## 3. AI 生產、複核與失敗分流

- 預設沿任務已核定的 Notebook 產出→AGY 複核→Codex 處理疑義；必要時請 Claude 核具體爭點。保留原題圖、完整題組、原官方鍵／Word 資源、教材印刷頁與 SHA。學生線上不即時查 AI。
- 每批送出前核帳號、來源、request SHA；送出／收回／marker 留 journal。已有完成回覆不得重送；解析修正與頁碼補正不等於重新向模型發問。
- 區分初始化失敗、格式錯誤、quota／網路錯誤、工具探針缺證據、**模型明確拒絕**與真題內容疑義。沒有實際額度證據，不把 model-unavailable 冒稱額度用完。
- 沒有 probe／拒絕事件時只能記「尚未取得證據」。允許在原授權內有界診斷；遇明確拒絕不得改 prompt、換模型、關 hook 或偽造事件繞過。同一失敗約三次且原因不明，先停同一路徑並做結構化診斷，不反覆猜測。
- **停一組探針，不等於停整個長線任務。** 已核通過的題目、其他批次、其他科目、教材／本機前處理、SQL／UI／正式回讀等可獨立工作繼續做。只有維持完整題組與存取限制的通過子集才可發布，不能為了發布拆壞共同素材。
- 替代模型／整批替代複核要核既有授權及訂閱範圍。「Claude 處理必要疑義」不能自行冒稱「整批全部轉 Claude」已獲明確同意。若確需新選擇，在側邊問一次並保留問題，**等待期間照做不依賴該答案的工作**。
- 不付費 API fallback、不啟用信用額度超支、不把模型拒絕當成可移除安全邊界的理由。工具無法使用與題目內容不可靠分開記錄，不能拿另一項正常就宣稱整題已複核。

## 4. 不因一項阻塞停止所有科目

每次完成／失敗／人工問題後，都更新下一個可執行工作：

| 情況 | 保留／阻擋範圍 | 仍應執行 |
| --- | --- | --- |
| Drive 網頁停密碼頁 | 該 web 通道；未證明其他通道失效 | 查既有桌面掛載／可見帳號與只讀 API preflight；無新媒體批次及其他科目繼續 |
| 書商 CAPTCHA／人工登入 | 該來源下載，保存精確 target | 用現有已驗教材做其他批次，不代過驗證碼、不反覆詢問 |
| AGY 明確拒絕探針 | 該執行路徑，真題未送則保持未送 | 保存診斷；完成已複核子集的後續關卡，處理其他可行批次／科目 |
| 等使用者決定替代複核 | 依賴該選擇的題目 | 其他已有授權工作；不能把預選或經過時間當答覆 |
| 缺某圖／配頁疑義 | 該題及依賴題組 | 不受影響題目；不得補畫假裝原圖或硬配頁 |
| 發布鎖由別人持有 | 當次發布，不能刪鎖 | 離線製作／驗證，依發布SOP報告，不擅自換發布方式 |

不得因「跑了兩小時」「剛完成一小段」「只剩某一批有疑義」就主動結束全部工作等待一句「繼續」。確實已無任何不依賴人工動作的工作時，才列出每條工作線的具體阻塞證據，說清楚已完成數與待處理數。執行環境若中斷或無法持續，誠實記錄，不聲稱背景仍在執行。

## 5. 圖文與教材的固定品質規則

- 課本印刷頁碼為主，與 PDF 頁序分開；整頁參照，一題可多頁、應用題可標相關觀念頁，保留拉頁。既有解析也重新核對。頂溪三／六與土城四以課本為主；不足查教冊，學生端只作文字補充並註源；不參考習作。中正九可提供完整教冊頁及解答，依當次範圍標示歷年參考。
- 學習重點給老師，學生解析用短句與適齡語言；數值算對也要核圖、格數、選項、公式與教材支持範圍。兩個 AI 一致不是證明。
- 一般題庫可依證據最小改寫，完整保留原件與修訂紀錄；考古卷保留原貌並加勘誤，爭議題不硬開自動計分。作答欄位與真實作答目標對齊，不以空格數或圖片占位猜答案。
- 分數依 [分數與公式 QC](past-exam-playbook.md#分數與公式一般題庫考古卷共同必查) 處理：題幹／選項／表格／解析都查。WMF 可見值與 OLE 快取不同、原件 SHA 與媒體 SHA 不同；大分母、帶分數、未知／裁切公式都要處理，塗色等真正題意圖保留。

## 6. 發布是完整的一段，不只把分析檔寫出來

1. 內容／原鍵／印刷頁／出處及修訂固定，現行 validator 通過；學生資料與未揭答保護保持。
2. 真資料庫交易回滾、正錯判分／非法輸入／初始隱私／跨人跨級匿名教材授權，以及正式共用元件桌機手機驗證通過。
3. disabled 匯入→逐筆等值讀回→fingerprint 守衛啟用→啟用後回滾及正式回讀。改候選後換驗收版本，不沿用不同 SHA 的 receipt。未知提交結果先核 journal／readback，不能盲重試。
4. 固定 study source／版本不能直接改內容或關 trigger。修復要用既有新版本機制，保留原作答、題序、選項ID／順序、判分、計時、進度與獎勵。
5. Supabase CLI 若共用同一臨時登入角色，資料庫操作串行，避免角色競爭；不要讓多個 import／test worker 同時使用它。瀏覽器亦依選定實例及段鎖序列化。
6. 更新老師備課檢視、可公開的收據與私有接續狀態。一般題庫、考古卷、來源題數、作答位置、已分析與實際上線分開計數。驗證通過且已授權就發布，不再重問每個小段；前端發布仍遵守只從 main 的正式腳本。

## 7. 瀏覽器、視窗、磁碟與免費用量

- 保留使用者指定的 Notebook 本體登入，不默換分身重新請登入。使用 shared launcher 租約／心跳、worker註冊、精確target及 finally釋放；其他測試使用可分配實例。不要掃全部 profiles 或接管使用者 Chrome。
- 使用者已要求背景執行時，走 supervisor 真正的 background 分支；run 記錄須誠實標 viewer=false／background=true，保留 canary、OAuth、tool boundary、Git、marker與SHA。完成才關確切自有頁籤／viewer，不刪雲端Notebook來源、不關其他人的視窗。等待人工輸入時不可讓背景工作搶前景。
- 大檔／TEMP用已核定工作碟。每科完成後清可重建暫存，保留原件／審查／正式收據；刪除前核絕對路徑與所有權，既有自動審查拒絕不可重試繞過。
- 實查當期 Cloudflare 方案、帳戶全體與目標 Worker 用量／錯誤，記時間與證據；網頁值無法確認就報未知。不能用資產數推請求數，也不能把Google模型呼叫、本機QA或DB metadata grant算成Worker下載。接近已核免費上限時停新增會耗用該資源的操作，其他離線工作繼續；不啟用付費／overages。

## 8. 跨對話交接必須由接手者驗收

- 交接須含：最新正式數量及版本／PR、不可重跑的批次、帳號角色與通道、確切私有檔案／工具、目前鎖與worker、可續跑命令、待答問題與依賴範圍、下一個可執行工作、容量／用量證據時間。
- 將本SOP作為必讀入口，私有附錄放帳號與路徑，不把公共SOP寫成只適用單次檔名的操作稿。舊版本資訊只當歷史，不覆寫新對話後來已完成的工作。
- 由接手對話實際回報：讀到哪版SOP、如何分清三種登入、當前正式基準、哪些批次保留及現在立即執行哪一步。只說「已收到」「已讀完」不算操作驗收。
- 對話封存失敗不阻止依可靠檔案接續，也不冒稱完整封存成功；有爭點才回看原生對話。送出交接後停止兩邊同時操作同一工作線。
