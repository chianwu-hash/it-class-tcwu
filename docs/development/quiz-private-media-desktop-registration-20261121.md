# 桌面同步與窄授權的受控媒體登記

本輪46既有過程修正版、44原題算式及7重量直式共需60個不同媒體。既有2個私有Drive／Worker素材下載SHA相符，直接重用；新增58個，不重傳既有素材。來源與網站尚未啟用／發布。

## 桌面新增檔案與既有窄授權

先核實Drive桌面版目前可見的核定儲存帳號，以及由該帳號開啟的真實G槽掛載；API另核實about帳號、既有私有parent及owner-only權限。不能從網頁登入狀態推論桌面版，也不能從磁碟代號推論帳號。

直接從桌面新增的一個範例，本機複製SHA相符，但既有窄授權API看不到；不能因此聲稱同步或遠端供圖通過，也不擴大OAuth權限。該初始範例留在私有驗證紀錄，不納入正式58筆索引。

本輪先以一個範例證實以下路徑，再處理58個素材：

1. 在同一個已核私有parent，以既有窄授權API登記受控資料夾與空白檔案，先保存固定fileId與預期SHA的journal。這一步只建立索引，不傳圖片內容。
2. 等待已登記檔案在已核桌面掛載中實際出現；不猜路徑另建同名檔，不用新權限讀未授權檔案。
3. 對既有空檔原位寫入圖片，保留fileId；非空檔必須已等於預期SHA，否則停止，不能覆蓋未知內容。
4. 先核本機SHA，再逐檔經API重新讀取原fileId、private owner-only權限、parent、名稱、MIME、大小及下載SHA。只有全數符合，才登記正式SHA屬性、Worker允許索引與資料庫媒體映射。

空白索引、桌面複製成功、同步中都不是已上傳或已可供圖。遠端大小為零才列待同步；非零但大小或下載SHA不符、已刪除的檔案都列衝突，保存實際大小及已取得的SHA，不登記下游索引。保留固定fileId，不反覆配置新ID、重傳或重啟工作程序。恢復時重新核實身分；既有檔案不得因名稱相同就覆寫。中斷留下的非空檔即使前段位元組相符，也不能據此覆蓋；保留原檔與journal，另核實復原方案。維持原窄授權，沒有新增OAuth權限或分享權限。

受控資料夾只容納已登記清單中的檔案，必須位於已核身分證據的掛載根目錄內；初始直接複製範例保留在另一資料夾。桌面版曾顯示23項同步錯誤，本批以58個固定fileId的遠端權限與完整下載SHA獨立證實成功，不宣稱其他錯誤已修復或與本批無關。
