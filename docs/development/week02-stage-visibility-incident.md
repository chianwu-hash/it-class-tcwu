# 三年級第 02 週：下一關檢查按鈕無反應

日期：2026-09-10

## 原因與修復

`week02-typing-ui.js` 以 `.current` 指定目前可檢查的關卡，過關後等學生按「下一關」才切換。共用 typing 模組保存成功後會移除下一關的 `.hidden`，代表該關已解鎖。

先前將 `.stage` 改為 `display:block`，導致已解鎖、尚未切換的下一關提前顯示。學生直接在那一關按「檢查數字」，會被 UI bridge 的 `id !== current` 條件忽略，沒有回饋。重新整理時 bridge 依遠端進度重新選定目前關卡，所以暫時恢復正常。

修復為 `.stage{display:none}`，只讓 `.stage.current` 顯示；`.hidden` 仍維持最高優先序，避免未解鎖關卡出現。一般任務與數字投遞員兩頁同步更新 CSS 版本。驗證、登入與 Supabase 保存邏輯不變。

## 已驗證

- 在正式頁面重現：第一關完成後，第二關提前顯示，但第二關按鈕無回應。
- 在 AI 工作瀏覽器套用本機修正 CSS，任務一連續完成第二至第四關；測試錯誤答案提示與正確答案保存，每次僅顯示目前關卡。
- 任務一重新整理後從遠端接回第四關完成狀態。
- 坐姿答題五題與視窗操作五步完整完成，延伸任務立即解鎖。
- 數字投遞員五關連續完成，包含第三關起預填錯字修正、第四關依序投遞，重新整理後遠端完成狀態正常。
- 測試沿用使用者指定的課堂身分卡 30130；測試完成記錄保留。

## 回歸檢查

日後調整關卡 CSS，必須用學生看得到的「下一關」按鈕連續走完整組活動，不能只呼叫 `checkLevel()` 或只確認下一關的 `.hidden` 已移除。確認過關後仍僅有一個 `.stage` 可見，且與 `.current` 一致；接著檢查重整接回與最後一關保存。
