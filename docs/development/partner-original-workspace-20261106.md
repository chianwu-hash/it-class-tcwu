# 夥伴練功沿用原答題操作

實班回饋指出：先前只共用 ABCD 選項呈現，送出按鈕仍藏在題目內，並未沿用原答題介面的操作。學生需要捲動並在多個按鈕間找送出位置。這次以原個人頁的 `createQuizWorkspace` 與 `quiz-workspace.css` 為直接共用來源。

## 固定操作契約

- 題目滿版呈現；一般桌機使用原題目／解題小幫手左右分欄，長題與含文字輸入的考古題依原工作區規則改為可捲動排版。
- 底部沿用同一個固定白色操作列，右側只有一個主要操作：送出答案／送出訂正 → 下一題；本人全部完成後顯示等夥伴，伺服器開放後轉為共同回顧；已完成則可到共同紀錄冊。
- 固定送出按鈕透過原 HTML form 的 `form` 屬性提交，保留原生必填檢查、原小隊 `expectedAttempt` 與重試路徑；不調用個人測驗控制器，不寫入個人卷、資料庫遷移或獎勵。
- 考古題組仍完整呈現，每次只送目前填寫／操作的小題，按鈕顯示小題序；其他小題不代送。不能稱為整包原子送出。
- 小隊資訊與流程分頁收進「題目與小隊」，換題選單與跳題收進原工作區的「儲存與提示」；請教／標記收在小幫手的摺疊區。共同營地保留單一懸浮入口及未讀提醒，避開固定操作列，不自動展開。
- 題目與輸入 DOM 仍沿既有局部更新保護；隊友消息不重建目前選項。切換至共同回顧／紀錄冊或離開時清理工作區的 body class、觀察器及事件，避免影響其他頁。

共用工作區僅新增相容的 `refresh()` API，供穩定 DOM 的小隊控制器在狀態文字、底部高度與選單改變後重新量測。原個人頁仍使用原 `apply/reset/destroy`，沒有改動其認證、送答或計葉；不能把只共用選項樣式稱為已沿用原操作介面。
