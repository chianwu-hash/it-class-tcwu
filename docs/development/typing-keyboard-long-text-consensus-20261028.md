## 已查核原因

`shared/typing-tools.js` 的 `buildTypingToolsHtml()` 將面板固定在右下角，沒有高度上限，也沒有獨立的提示捲動區。`renderZhuyinKeyboardGuide()` 在鍵盤之後，為每個音節產生一列注音；長文使整個面板向上超出視窗，鍵盤與關閉鈕一起離開可視範圍。整篇所需的鍵同時標黃，也會降低找字提示的辨識度。

第 08 週第 5 關與第 09 週第 5 關、再練習長句都使用此流程。英文 renderer 則把整段轉小寫、刪除非字母後列出完整按鍵序列，無法完整表達原題目的大小寫、空白、標點與換行要求。

上述結論依原始碼確認；沒有把 CSS 高度推算當成瀏覽器實測。

## 建議首版

1. **固定鍵盤、標題與關閉鈕。** 面板以可視高度為上限；一般教室桌面只讓下方的提示區捲動。不要縮到字看不清。
2. **注音改成緊湊字卡，長文分成短段。** 中文先依標點與換行分段，仍過長時按漢字數切成有上限的小段；英文先依行、再在單字邊界分組，單一長單字完整保留。原文的大小寫、空白、標點與換行資訊不得丟失。
3. **一次顯示一小段。** 提供「上一段／下一段」與「第 2／4 段」；短字詞不增加多餘導覽。可展開「看全部注音」或「看全部按鍵」，仍限在提示區捲動。
4. **點選查字是可選操作。** 學生點某張中文字卡，就只標黃該字的注音與聲調鍵；再點一次或按「看整段」恢復。不要要求每打一字都按「下一字」，也不記錄查過哪些字。
5. **標點沿用既有工具。** 標點卡可引導查看「標點符號表」；未經實機核對，不新增「按某鍵必定輸出某全形標點」的說明。
6. **低高度明確降級。** 放大、低高度或手機放不下時，採可捲動參考面板，關閉鈕持續可見；不保證同屏顯示完整鍵盤、所有提示與輸入框。尺寸下限和每段字數均須實測後決定，8 字只能作初始試驗值。

## 暫緩

- 自動依輸入長度跳字、跳段。IME 組字、同音字選錯、游標中途修正、標點與換行都可能讓單純的 `value.length` 判定失準。
- 強制逐字點選、逐鍵評分或自動送出。Enter 選字維持原有語意，不當成檢查過關。
- 可拖曳、可調大小、另外建立手機專屬模式等額外操作，留待首版實測後評估。

草稿還原目前已發出 `input` 事件，這是 Codex 實讀 `restoreDraft()` 後補正 Claude 第一輪的假設。未來若增加跟隨功能，可依還原內容重算提示位置；草稿內容不構成正式過關紀錄。

## 實作邊界與待驗收

- 修改共用 `typing-tools.js`；保留既有回傳字串的 `getKeyboardTarget`、`getZhuyinTarget` 和既有 renderer 的相容呼叫，不要求所有週頁重寫。
- 第 09 週同時透過共用英文刷新與頁面自訂中英刷新重畫，是本次發現的整合問題。Claude 建議另列修正；Codex 判斷正式整合時至少要驗證並消除同次操作互相覆蓋提示狀態的情況，不另外擴成整站重構。
- 使用標準按鈕與可見焦點。滑鼠操作可評估在 `mousedown` 阻止焦點轉移，但不是已驗證的 IME 保證；鍵盤 Tab／Enter／Space 必須仍可操作，觸控另測。不用反覆 `focus()` 或自動捲動打斷學生。
- 1280×720 檢查第 08 週第 5 關、第 09 週長句及換題後：鍵盤和關閉鈕可見；輸入位置、候選字視窗不被遮住。確認鍵盤與標點工具不重疊，可採一次開一個。
- 200% 縮放與低高度測可讀性及關閉操作，不以任意縮小鍵帽通過驗收。
- 補測 50 字無標點中文、超長英文單行、單一長單字、重複漢字、標點、換行與注音音節數不符的防護。
- 真實 Windows 微軟注音組字與候選窗開啟時，操作字卡／分段；記錄組字是否被送出、取消或保留，確認不誤觸檢查。DOM 合成事件不足以取代此驗收。
- 切關、再練習與草稿回復後，提示須對應目前題目；不得新增登入、進度、解鎖或努力樹寫入。
